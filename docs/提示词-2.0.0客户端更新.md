# 给 APK 客户端的更新提示词（FnReader 2.0.0）

> 直接把下面整段复制给负责改 APK 的模型。

---

你在维护一个 Android 阅读 App（Legado 底座，包名 io.legado.pro）。它通过「软总线」接入 NAS 上的
FnReader 服务端：App 常驻一个轮询循环，从服务端领任务、在本地执行、把结果回传。

服务端已升级到 **2.0.0**，新增了一类任务 `bookinfo`。你需要在客户端补上它的处理。
接口文档：`https://github.com/TZYLXS/FnReader/blob/main/docs/简介补全接口.md`

## 背景（为什么加这个任务）

服务端抓书籍简介这条路是残的：起点详情页返回 202 反爬挑战页，晋江书名有字体混淆，
所以网页端「详情页」经常没有简介。而 App 里有登录态和 WebView，用 Legado 自己的详情规则能拿到。

约定：**服务端缺简介时下发 `bookinfo` 任务，App 抓完回传，服务端写回书架。**

## 任务格式

在 `GET /api/m/remote/pending` 的返回里会出现：

```json
{
  "id": "53d126dc722f",
  "type": "bookinfo",
  "payload": {
    "bookUrl": "http://www.feisuwx.org/book/274/274864/index.html",
    "source": "https://www.aixiawx.com/",
    "name": "黎明之剑",
    "author": "远瞳"
  },
  "age": 1200
}
```

- `payload.bookUrl`：必用，就是详情页地址
- `payload.source`：书源地址，可能为空；为空时用 `bookUrl` 的 host 去匹配 `BookSource.bookSourceUrl`
- `payload.name` / `author`：辅助信息，用于构造 Book 对象

## 回传格式

```http
POST /api/m/remote/result
X-Api-Token: <令牌>
Content-Type: application/json; charset=utf-8

{
  "id": "53d126dc722f",
  "deviceId": "<设备 id>",
  "ok": true,
  "data": {
    "intro": "高文穿越到一个即将被魔潮吞没的世界……",
    "author": "远瞳",
    "coverUrl": "https://…/cover.jpg",
    "kind": "奇幻",
    "wordCount": "500万字",
    "lastChapter": "第1594章 8：05",
    "totalChapterNum": 1594
  }
}
```

字段**全部可选**，拿得到才给，拿不到的省略（不要传空串以外的占位值）。

失败时：`{ "id": "...", "ok": false, "error": "原因" }`

## 必须实现的改动

### 1. 轮询循环加分支

```kotlin
when (job.type) {
    "search"   -> handleSearch(job)
    "toc"      -> handleToc(job)
    "content"  -> handleContent(job)
    "bookinfo" -> handleBookInfo(job)   // ← 新增
    else       -> postResult(job.id, ok = false, error = "不支持的任务类型：${job.type}")
}
```

### 2. handleBookInfo 实现

```kotlin
private suspend fun handleBookInfo(job: RemoteJob) {
    val p = job.payload
    val bookUrl = p.optString("bookUrl")
    if (bookUrl.isBlank()) { postResult(job.id, false, error = "缺少 bookUrl"); return }

    val source = appDb.bookSourceDao.getBookSource(p.optString("source"))
        ?: appDb.bookSourceDao.all.firstOrNull {
            it.bookSourceUrl.toHttpUrlOrNull()?.host == bookUrl.toHttpUrlOrNull()?.host
        }
    if (source == null) { postResult(job.id, false, error = "没有匹配的书源"); return }

    val book = Book(
        bookUrl = bookUrl,
        origin = source.bookSourceUrl,
        name = p.optString("name"),
        author = p.optString("author")
    )

    val info = try {
        WebBook.getBookInfoAwait(source, book)
    } catch (e: Exception) {
        postResult(job.id, false, error = e.localizedMessage ?: "抓取失败")
        return
    }

    val data = JSONObject().apply {
        info.intro?.takeIf { it.isNotBlank() }?.let { put("intro", it) }
        info.author?.takeIf { it.isNotBlank() }?.let { put("author", it) }
        info.coverUrl?.takeIf { it.isNotBlank() }?.let { put("coverUrl", it) }
        info.kind?.takeIf { it.isNotBlank() }?.let { put("kind", it) }
        info.wordCount?.takeIf { it.isNotBlank() }?.let { put("wordCount", it) }
        info.latestChapterTitle?.takeIf { it.isNotBlank() }?.let { put("lastChapter", it) }
        if (info.totalChapterNum > 0) put("totalChapterNum", info.totalChapterNum)
    }
    postResult(job.id, ok = true, data = data)
}
```

### 3. 回传时一定带 deviceId

服务端用 `deviceId` 统计是哪台设备干的活。没有就传设备 id 的哈希，保持稳定即可。

### 4. intro 如果是富文本，先转纯文本

Legado 的 `intro` 有时带 `<p>`/`<br>`。回传前用 `HtmlFormatter.formatKeepImg(intro, null)`
或等价方法去标签，否则网页端会把标签当文字显示。

## 不要这样做

| 错误写法 | 后果 |
| --- | --- |
| `else -> 直接忽略任务` | 服务端等 10 秒超时，简介永远补不上 |
| 回传 `{"intro": ""}` | 服务端会当作"没有简介"，不会重试 |
| 回传 HTML | 网页端显示成 `<p>…</p>` |
| 不在 `deviceId` 里带设备标识 | 服务端统计不到，排查困难 |
| 类型判断写死 `search/toc/content` | 新类型一律报"不支持"，就是现在的问题 |

## 自测清单

```
□ 装包后等 1 秒，服务端 /api/bus 能看到本设备（online: true）
□ 让服务端触发一次：curl "http://<NAS>:1122/api/detail?url=<无简介的书>&origin=<源>"
□ 查 /api/remote/stats 的 recent 里出现 type: bookinfo、ok: true
□ 再查 /api/detail，book.intro 非空，且响应里有 via: "phone"
□ 断网/详情页打不开时，回传 ok:false，服务端仍能正常返回（不应报 500）
```

## 相关信息（同一 App 里的其它软总线任务，别改坏）

| 任务 | 用途 |
| --- | --- |
| `search` | 服务端解析不了的源，交给 App 搜 |
| `toc` | 目录 |
| `content` | 正文 |
| `rank` | 起点榜单（可选） |
| **`bookinfo`** | **本次新增：详情/简介** |

这些任务都在同一个轮询循环里，`handleBookInfo` 加进去后不要影响其它分支的 `ok:true`/`ok:false` 语义。
