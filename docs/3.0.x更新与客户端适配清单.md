# FnReader 3.0.x 更新说明与客户端适配清单

- 更新日期：2026-11-22
- 服务端版本：`3.0.0` → `3.0.1` → `3.0.2`（当前线上 `3.0.2`）
- 仓库：`TZYLXS/FnReader`，分支 `main`
- 适用对象：网页端用户、APK 客户端开发者、自建服务器用户

## 一、这次更新了什么

### 1. 亚马逊书城界面（Web 端，默认主题）

- 顶部深色导航（`#131921`）+ 整行搜索框：范围下拉（图书 / 作者）+ 放大镜按钮，回车即跳搜索页并带入关键词
- 分类条：全部 / 在读 N / 未读 N / 本地电子书 / 设置，选中项有滑动下划线动画
- 结果列表：封面 + 书名 + 作者/类型/章数 + 星级（按阅读进度填充）+ 进度条 + 黄色「继续阅读」按钮
- 左侧筛选（桌面）：格式（全部 / 本地电子书 / 网文）、阅读状态（在读 / 未读）
- 排序：最近阅读 / 书名 / 阅读进度
- 响应式：手机（<640）、小屏手机（≤375 / ≤339）、平板、桌面（≥900）、超宽屏（≥1280）
- 封面只展示图片，不再用书名首字占位

> 老用户升级后主题仍是原来配置的主题，需要在「设置 → 阅读 → 主题」手动切到「亚马逊书城」。

### 2. Java 21 目录引擎（服务端，默认启动）

- 目录解析完成后的去重 / 排序 / 标题清洗交给常驻 Java 21 进程（设计来自原 debug 分支）
- 默认随服务启动，设置页「TRE 引擎 → Java 目录引擎」可开关，状态显示 `运行中 · Java 21.0.x · 虚拟线程 · 端口`
- Java 不可用时自动回落内置 Node 实现，功能不受影响
- 运行时查找顺序：`app/server/java/*.class` → `app/server/runtime/java` → `LEGADO_JAVA` → `/var/apps/java-21-openjdk/target/bin/java` → 系统 java

### 3. 多线程解析池与 TOC 队列（服务端）

- `worker_threads` 解析池：复杂书源（含 `<js>`、`@js:`、`java.*`、慢 `java.ajax`）不再阻塞主线程
- 目录解析走独立队列，不挤占搜索；软总线按权重限制在途任务（`book` 3 个、`content` 2 个）

### 4. 书源同步接口补齐（**客户端需要适配**）

- `POST /api/m/sources`（全量推送）：入库前 `normalizeSource()`（补 `type`、`ruleSearch/BookInfo/Toc/Content`、`enabled`、`@js` 运行时方法），写 `lastUpdateTime`，同批重复 URL 只留第一条并返回 `duplicated`
- `POST /api/m/sources/sync`（双向 LWW）：新增/更新都走规范化，删除走 `deleted` 数组
- 服务启动加载历史书源时自动补规范化，重启后运行时方法不丢失

### 5. 修复

- 书架点击「继续阅读」无响应（点击事件只认旧卡片结构）
- PC 端搜索下拉比输入框矮 8px（旧 `padding-bottom` 残留）
- 二级页返回按钮错位 / 主题切换后不刷新
- 分类筛选后页面宽度跳动（滚动条出现消失）
- `POST /api/books` 去重后 `sanitizeBook(null)` 空指针 500
- Java 引擎在只带预编译 class 的 FPK 中无法启动
- debug 版更新检查改读本地 `update/latest.json`（阿尔法仓库已归档）

### 6. 发布链路与文档

- `auto-release` 不再用本地旧 `docs/更新日志.md` 覆盖 dist 新版本（v3.0.0/v3.0.1 Release 说明取错版本的根因）
- 文档新增 §18 书源管理接口；修正 AI 构建指南里 `/api/m/sync` 误写成 `GET/POST`
- v3.0.2 起 tag 内容、Release 说明、更新日志三者一致

## 二、客户端必须适配的功能

> 结论：**服务端已经全部就绪，客户端这侧还没实现**。下面每一项都是「服务端已支持、客户端待接」。
> 协议细节见 `docs/APP同步接口.md`；本地可用 `tools/mock-client.js` 一键验收。

### 0. 通用约定

| 项 | 约定 |
| --- | --- |
| 鉴权 | 请求头 `X-Api-Token: <token>` 或查询参数 `?token=`；令牌在「设置 → 手机接入」查看/重置 |
| 编码 | 请求/响应均 `application/json; charset=utf-8` |
| 请求体上限 | 32 MB（整包 1000+ 书源约 8 MB，可一次推完） |
| 时间戳 | 统一毫秒 `Date.now()` |

### 1. 书源全量推送（新增源 / 覆盖已有源）

```http
POST /api/m/sources      X-Api-Token: …
[ { "bookSourceName": "…", "bookSourceUrl": "…", "ruleSearch": { … } }, … ]
```

- 也接受 `{ "sources": [ … ] }`
- 响应：

```json
{ "ok": true, "added": 0, "updated": 1150, "duplicated": 0, "total": 1150 }
```

- 客户端要做的：书源页「同步/上传到服务器」时，把本地书源数组（可分批）推上来即可
- 服务端会自己规范化、去重、写 `lastUpdateTime`，客户端**不需要**预加工

### 2. 书源双向同步（含删除）

```http
GET  /api/m/sources/sync?since=<毫秒>     # 拉增量
POST /api/m/sources/sync                  # 推本地改动
```

推送体：

```json
{
  "since": 1794148000000,
  "updated": [ { "bookSourceUrl": "https://…", "bookSourceName": "…", "lastUpdateTime": 1794149100000, "ruleSearch": { … } } ],
  "deleted": [ { "bookSourceUrl": "https://…", "lastUpdateTime": 1794149110000 } ]
}
```

响应：

```json
{ "ok": true, "applied": 2, "skipped": 1, "pull": [ … ], "pullDeleted": [], "serverTime": 1794149022425, "total": 1254 }
```

- 判定：客户端 `lastUpdateTime` **大于**服务端 → 覆盖；**小于等于** → 忽略并把服务端版本放进 `pull`
- 客户端要做的（关键）：
  1. 书源**新增/编辑/删除**时写 `lastUpdateTime = now` 并进本地变更队列
  2. App 启动 / 每 10 分钟 / 手动同步时推一次，成功后清队列
  3. 用 `pull` / `pullDeleted` 覆盖本地
  4. **删除必须走 `deleted`**——`POST /api/m/sources` 全量推送无法表达删除

### 3. 书架加书回传

```http
POST /api/m/books
{ "bookUrl": "…", "name": "…", "author": "…", "origin": "…" }
```

- 触发点：搜索页/详情页「加入书架」、换源后重新加书、批量加书
- 响应 `{"ok":true,"added":0,"updated":1,"total":42}`；服务端已处理去重合并

### 4. 阅读进度回传

```http
POST /api/m/progress
{ "bookUrl": "…", "index": 12, "pos": 0, "title": "第13章 …" }
```

- 批量：`POST /api/m/progress/batch`，体 `{ "items": [ …同上… ] }`
- 触发点：翻页（防抖 2~5 秒）、退出阅读、App 切后台
- 响应 `{"ok":true}`；服务端会把 `durChapterIndex` 写回书架，网页端实时同步

### 5. 封面上传

```http
POST /api/m/cover
{ "bookUrl": "…", "mime": "image/png", "data": "data:image/png;base64,…" }
```

- 也支持 `?bookUrl=` + 原始二进制体（`Content-Type: image/*`）
- 响应 `{"ok":true,"coverUrl":"http://…/api/covers/xxxx.png","size":70,"book":true}`
- 单张上限 8 MB；命中书架里的书时自动回写该书的 `coverUrl`

### 6. 缓存正文回传

```http
POST /api/m/cache
{
  "book": { "bookUrl": "…", "name": "…" },
  "chapters": [ { "index": 0, "title": "第1章", "raw": "正文…" } ]
}
```

- 服务端落到 `<下载目录>/cache/<书名>/`，布局兼容 Legado
- 本地已有同名电子书时会返回 `skipped:true`（`skipIfLocal:false` 可强制写）
- 响应含 `dir`、`chapters`、`bytes`

### 7. `/api/m/sync` 只能 GET

```http
GET /api/m/sync?since=0&full=1      X-Api-Token: …
```

- 一次拉书架 + 进度 + 书源汇总（`full=1` 带完整书源对象）
- **没有 `POST /api/m/sync`**：推书源用第 1/2 条，推进度用第 4 条
- 返回结构未变：`app / version / serverTime / since / incr / shelf / shelfCount / progress / progressCount / sources / endpoints`

### 8. 客户端能力现状（2026-11-22 核对）

| 接口 | 服务端 | 客户端（yuedu-pro 补丁，APK 2.6.12.1） |
| --- | --- | --- |
| `GET /api/m/remote/pending` | ✅ | ✅ |
| `POST /api/m/remote/result` | ✅ | ✅ |
| `GET /api/m/info` | ✅ | ✅ |

## 三、客户端接好之后怎么验收

本地模拟客户端会把上面「客户端待接」的 6 类回传全部跑一遍并断言服务端状态：

```bash
node tools/mock-client.js http://192.168.1.233:18080 <令牌>
node tools/mock-client.js http://192.168.1.233:18081 <令牌>   # 对照端
```

实测两端 **8/8 通过**，覆盖：`sync` 拉取 → `books` 加书 → `progress` 单条 → `progress/batch` → `cover` 上传 → `sources/sync` → `cache` 落盘 → 清理。

书源全量推送单独验：

```bash
curl -X POST -H "X-Api-Token: <令牌>" -H "Content-Type: application/json" \
     --data-binary @bookSource.json http://<服务器>/api/m/sources
# {"ok":true,"added":0,"updated":1150,"duplicated":0,"total":1150}
```

## 四、升级注意（从旧版本直接升到 3.0.x）

1. **数据目录不变**：`/vol{n}/@appdata/legado-web`，`config.json` 按「默认值 + 旧配置」合并，书架/书源/进度都会保留
2. **首次打开会要求确认缓存位置**（`setupVersion` 变化），确认一次即可，不影响数据
3. **默认主题只对新装生效**，老用户沿用原主题，需手动切「亚马逊书城」
4. **Java 引擎默认开启**：NAS 没装「Java 21 OpenJDK」时会记一条启动失败日志并回落 Node；可在设置里关掉
5. **升级方式决定数据安全**：应用中心「升级/更新」保留数据；`appcenter-cli uninstall` 会删 `@appdata`，必须卸载重装前先备份：

```bash
cp -a /vol4/@appdata/legado-web /vol4/@appdata/legado-web.bak
```

6. 旧书源没有 `lastUpdateTime`：同步时以服务端版本优先；建议客户端首次接入时对全部书源打一次时间戳再推

## 五、真机联调记录（2026-11-23，debug 0.1.18）

MuMu 模拟器内阅读Pro 3.1.4.1 对接 NAS debug `http://10.5.4.70:1123`，按 A/B/C/D 四步验证：

| 用例 | 动作 | 结果 |
| --- | --- | --- |
| A 首次全量上传 | 手机端新增 2 个书源并触发同步 | NAS 1130→1132，`probe://mumu-1/2` 落入服务端 |
| B 手机端删除 | 删掉 probe-mumu-1 再同步 | NAS 1132→1131，服务端已无该源；**0.1.18 的字符串 `deleted` 修复在真机生效** |
| C 服务端改动回流 | 服务端改名 probe-mumu-2-srv（新 lastUpdateTime） | 客户端一轮同步后显示新名称；通知「书源同步：推 0 个　拉 1 个　飞牛 1131 个」 |
| D 清理 | 手机端删掉最后一个 probe 并同步 | NAS 回到 1130，probe 残留 0 |

遗留（客户端侧，下次打包处理）：

- 首次合并「上传 N 个」一次性通知会被前台常驻「待命中」覆盖，用户看不到 → 独立 notification channel/id；
- 同步结果只在通知里，覆盖后不可回看 → 建议写入 App 内「同步记录」；
- 点「同步」时偶发「解析失败：任务里没有书源地址」（`FnReaderRemote.source()` 空地址兜底），疑似空队列任务，需客户端侧过滤空 `bookSourceUrl`。
