# Legado 阅读 · fnOS 网页版（FPK）

把安卓「阅读 3.0 / Legado」的使用体验搬到飞牛 fnOS 上：**不用装安卓模拟器**，直接在 fnOS 桌面点开就是一个网页书架，支持导入 Legado 书源、搜索、加书架、看目录和正文。

- 安装包：`legado-web.fpk`（v1.0.1，约 551 KB）
- 已在测试机 `10.5.4.70` 安装并运行

---

## 1. 为什么不是直接编译原安卓源码

原项目是 Kotlin + Jetpack Compose 的原生安卓 App，界面无法在浏览器里渲染；Android 模拟器（redroid 等）在 NAS 上需要 KVM、资源占用大、手机端体验也差。

因此这里采用**复用 Legado 书源协议、重写运行层**的方案：

| 层 | 做法 |
| --- | --- |
| 书源规则引擎 | 用 JavaScript 重新实现 Legado 规则语法（CSS / XPath / JSONPath / 正则 / `@js:` 沙箱） |
| 服务端 | Node.js 单文件（esbuild 打包），读写 JSON 数据 |
| 前端 | 移动端优先的单页应用（书架 / 搜索 / 阅读器 / 书源管理 / 设置） |
| 运行环境 | 设置 → TRE 引擎 里显示 Node 版本 / V8 版本（升级 Node 后自动变化） |
| 打包 | fnOS FPK：统一网关入口 + 端口直连双入口，依赖系统 `nodejs_v22` |

所以你导入的 **Legado 书源 JSON 可以直接用**，不需要改格式。

## 2. 安装

### 方式 A：应用中心手动安装（推荐）

1. 打开 fnOS「应用中心」→ 右上角/设置中的「手动安装」
2. 选择 `legado-web.fpk`
3. 安装完成后，桌面会出现「Legado 阅读」图标

### 方式 B：命令行

```bash
appcenter-cli install-fpk /path/to/legado-web.fpk
appcenter-cli start legado-web
```

> 依赖 `nodejs_v22`，安装时会由应用中心自动拉起；如果启动失败，先确认该依赖已安装。

## 3. 打开方式

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 桌面图标（网关） | `/app/legado-web/` | 走 fnOS 统一网关，复用 NAS 登录态，推荐 |
| 直连端口 | `http://设备IP:1122/` | 不校验 NAS 登录，适合局域网/调试 |

桌面图标默认打开网关入口；`noDisplay` 的「直连端口」入口只在需要时使用。

## 4. 使用

1. **书源** → 右上角「导入」：
   - 粘贴 Legado 书源 JSON（数组或单个对象）
   - 或填书源订阅链接
   - 或选择本地 `.json` 文件
2. **搜索** → 输入书名/作者，可选「全部书源」或指定某个源；结果边搜边出
   - 默认**不搜正版接口源**（起点 / QQ阅读 / 掌阅 / 番茄 / 七猫等）；需要时点搜索页的「正版源」芯片，或在书源里只勾选想搜的源
   - 顶部会提示 `已跳过 N 个正版接口源`，属于正常行为
3. 点「加入书架」→ 自动拉取目录
4. **书架** → 点书封继续阅读；长按书封可删除
5. 阅读页：上一章/下一章、右上角 `☰` 目录、`Aa` 调整主题/字号/行距；进度自动保存

### 自适应布局

- 手机（<640px）：单列书架 + 横向「最近在读」，底栏贴底、适配刘海屏安全区
- 小屏手机（≤375px，iPhone SE / iPhone 5 / 华为 P30）：顶栏品牌独占一行、搜索框整行，
  列表封面 84px（≤339px 时 78px）、按钮与筛选控件紧凑化，主题/书源等下拉不再截断
- 平板（640–899px）：封面网格 4–5 列，继续阅读卡片放大
- 桌面（≥900px）：内容居中限宽 1120px，书架最多 6–8 列，底栏图标随内容居中
- 超宽屏（≥1280px）：封面更大更密，阅读栏可适当加宽
- 阅读正文：字号 `clamp()` 自适应，横屏矮屏自动压缩顶部留白

## 5. 兼容范围

已实现（按 Legado 3.x 规则语义）：

- 规则连接：`||` 备选、`&&` 拼接、`{{key}}` / `{{page}}` 变量
- 选择器链：`id.chapterlist@p@a`、`.btn@a.0@href`、`span.title@text`、`[property$=author]@content`
- 前缀写法：`class.x` / `tag.a` / `id.x` / `text.查看完整目录`
- 索引：`a.0`、`p!0`、`li.1:2:3`、`.-1`
- XPath：`//div[@class="x"]/a/@href`、`@XPath:`
- JSON：`$.data.list[*]`、`data.books`、嵌套 JSON 字符串、`{{$.field}}`
- 取值：`@text` `@html` `@href` `@src` `@textNodes` `@ownText`，以及裸写 `text` / `href`
- 变量：`@put:{key: rule}` / `@get:{key}` / `{{var}}`
- 正则：`rule:regex`、`##替换##`
- 脚本：`@js:`（vm 沙箱，`java.ajax` / `base64` / `md5` / `put/get` / `result` / `baseUrl` / `book` / `source`）
- 流程：搜索（相对地址、GET/POST、单引号配置、charset）、详情、目录、正文（翻页、`replaceRegex`）

已知限制（这类书源需要 WebView / App 接口，服务端无法实现）：

- `{"webView": true}` 的源；页面由 JS 动态渲染（如目录靠 AJAX 加载）
- 需要签名算法、登录态、加密接口的 API 源
- 发现页（`exploreUrl`）、RSS、本地 TXT/EPUB、朗读、换源
- 正文只保留文字，图片忽略

### 书源太多怎么办

「书源」页支持按名称/地址/分组筛选，点「检测」会对**当前筛选结果**用热门书名试搜一遍，标出「可用 / 无结果 / 不可用」，
检测完点「停用未通过」即可只留下能用的源；搜索页随后默认走「仅可用」，速度快很多。

## 6. 数据与目录

| 内容 | 位置 |
| --- | --- |
| 应用文件 | `/var/apps/legado-web/target/`（→ `/vol{n}/@appcenter/legado-web`） |
| 数据（书源/书架/进度/设置） | `/var/apps/legado-web/var/`（→ `/vol{n}/@appdata/legado-web`） |
| 运行日志 | `/var/apps/legado-web/var/app.log` |

卸载会保留数据目录，重新安装后书架和书源仍在；需要彻底清理时手动删除 `@appdata/legado-web`。

> 注意（2.1.0 起）：网页端第一次打开、以及每次升级后，会先弹出「先确认缓存保存位置」页。
> 确认后才会写入 `downloadDir` 并**开启软总线**（手机端任务接收）；未确认时 App 轮询 `/api/m/remote/pending` 会收到 409。
> 缓存位置可填任意绝对路径（会自动创建 `<目录>/cache`），也可以在设置页的「自定义目录」里随时改。

### 本地电子书（2.2.0 起）

- 设置 → 下载 → **扫描目录**：检查 `下载目录/ebook`（或设置里的 `ebookDir`）下的 epub/mobi/txt/pdf
- 扫描到的书用 `ebook://<sha1>` 访问，`/api/toc`、`/api/content` 直接读解析产物
- 本地已有同名电子书时，客户端同步会**跳过这本书**（响应 `skipped:true`）
- 客户端只有 TXT 时，服务端用本地 Python 引擎分章，不再保存 `.nb` 缓存

### 缓存

- App 上传的缓存落在「下载目录/cache/<书名>/」，同一本书**重复同步会复用原目录**，不会再出现「书名 (2)(3)…」一堆同名目录（2.1.0 起）
- 历史遗留的重复目录可调 `POST /api/cache/dedupe` 归并（按「书名+作者」合并，保留文件最多的一份）
- 章节正文缓存在 `/var/apps/legado-web/var/cache/`（默认保留 14 天，超过 200MB 自动清理旧文件）
- 打开一章后会后台预取后面两章，翻页基本即时完成
- 想强制重新抓取某章：删掉对应缓存目录，或在书架长按「刷新目录」后重进

```

├── manifest                 # appname=legado-web, 依赖 nodejs_v22, 端口 1122

```

重新打包：

```bash
bash work/tools/build-fpk.sh
# 产物：work/dist/legado-web.fpk
```

```bash
cd work/fnos-legado/app/server
```

## 附：加载速度优化（v1.0.2）

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 阅读下一章 | 每次 1–3 s 网络请求 | 约 20 ms（预取命中） |
| 重看已读章节 | 重新抓取 | 约 12 ms（内存/磁盘缓存） |
| 重新打开应用后再读 | 重新抓取 | 直接命中磁盘缓存 |
| 首页静态资源 | 未压缩 | gzip（app.js 23KB → 7.6KB）+ ETag 304 |

实现方式：章节正文按「章节 URL」落盘缓存（`var/cache/`，14 天 TTL、200MB 上限自动清理），
打开一章后延迟 400 ms 后台预取后两章，同一章并发请求会合并为一次抓取；
静态资源加了 gzip 与 ETag，二次访问返回 304。

## 附：整本下载为 TXT（v1.0.3）

**入口**

- 书架：长按书封 → 菜单里点「下载整本为 TXT」
- 阅读页：右上角 `Aa` → 设置面板底部「整本下载」

**行为**

- 后台抓取全部章节，底部出现进度条（`已下载 x/y`），可随时取消
- 完成后浏览器自动下载 `<书名>.txt`
- 文件格式：UTF-8（带 BOM，Windows 记事本不乱码），开头是书名/作者/来源，之后每章「标题 + 正文」
- 文件同时保存在 NAS：`/var/apps/legado-web/var/downloads/<书名>.txt`

**速度**

下载复用阅读时的正文缓存与预取，读过的章节几乎瞬时；实测 922 章的书约 40 秒完成，生成 7.6MB TXT。
首次下载一本没读过的书，耗时取决于书源站点的响应速度。

**章节顺序**

部分站点把「最新章节」放在目录最前面，服务端会自动识别并翻转为正常阅读顺序；
分页造成的重复章节会按 URL 去重。

- 强短语（如「机器学习」「neural network」）单独出现即可判定

命中后搜索页会显示：`🎓 识别为学术查询（机器学习），只搜 2 个学术书源　改搜全部`

点「改搜全部」就对全量书源搜索（比如书名里恰好带「算法」的网络小说）。

学术模式下不受「仅可用」限制——学术源通常没跑过体检，但只要分组是「学术」就会被搜索。

## 附：版本与更新日志规范（自 1.6.8 起）

每次改动都按同一流程发版：

1. 递增 `manifest` 的版本号（补丁位 +1）
2. 在 `更新日志.txt` / `更新日志.md` 顶部插入一条该版本的说明
3. 更新 `app.js` 里「版本 Vx.y.z」的显示
4. 重新打包 `legado-web.fpk`，更新日志随包发布到 `docs/changelog.txt`

一条命令完成 1–4：

```bash
python tools/release.py "修复了 xxx；新增了 yyy" --build

python tools/release.py "说明" --dry-run
```

注意：fnOS 的 `install-fpk` 不支持覆盖升级（会提示成功但文件不变），

## 附：解析引擎切换（v1.11.4）

设置页新增「解析引擎」区块，可以在两套规则引擎之间切换：

| 引擎 | 说明 |
| --- | --- |
| **Node 内置**（默认） | 原来那套，cheerio + 自研 XPath，跟分页目录、目录去重排序都支持 |

开关行为：

## Java 21 目录引擎（默认启动，2.7.0+）

目录解析完成后的「去重 / 排序 / 标题清洗」交给一个常驻的 Java 21 进程处理，
设计来自阿尔法仓库：单文件 `FnReaderJavaWorker.java`、无第三方 jar、只监听 loopback 动态端口，
Node ↔ Java 之间用 Base64 三列 NDJSON，避免给 FPK 引入 JSON 库。

- **默认启动**：服务起来后自动拉起 Java worker（日志 `Java 目录引擎已启动，端口 xxxxx`）
- **设置开关**：设置 → TRE 引擎 → 「Java 目录引擎」，右侧显示 `运行中 · Java 21.0.x · 虚拟线程 · 端口`
- 关闭后目录规范化回落到内置 Node 实现（`chapter-order.js`），功能不受影响
- 开关状态存 `config.json` 的 `javaEngine` 字段；`/api/engine` GET 返回 `java` 状态，POST `{javaEngine:boolean}` 切换
- 开启时会先做健康检查（`/health` 返回 `virtualThreads:true`），失败直接拒绝并保持关闭

运行时查找顺序：

```
app/server/java/FnReaderJavaWorker.class   （随 FPK 打包的预编译 class）
app/server/runtime/java/bin/java           （可选：随包的 jlink 精简运行时）
LEGADO_JAVA                                （环境变量指定 java）
/var/apps/java-21-openjdk/target/bin/java  （fnOS 应用中心的 JDK 21）
/usr/bin/java ...
```

也就是说：装了 fnOS 的「Java 21 OpenJDK」应用即可启用，不必额外打包 200MB+ 运行时；
没有 Java 时开关会显示启动失败原因，引擎保持关闭，阅读/搜索照常。

## debug 版的本地更新源（0.1.1+）

`legado-web-debug` 不访问 GitHub，检查更新时读本地文件：

```
<下载目录>/update/latest.json
# NAS 默认：/vol4/1000/2/update/latest.json（可用环境变量 FNREADER_UPDATE_FILE 覆盖）
```

文件格式：

```json
{
  "version": "0.1.2",
  "name": "FnReader debug 0.1.2",
  "notes": "这次改了什么",
  "releasedAt": "2026-11-22T10:00:00+08:00",
  "fpk": "/vol4/1000/2/update/legado-web-debug.fpk"
}
```

- 发新包：把 `legado-web-debug.fpk` 放进 `update/`，改 `version`（大于当前版本才会提示有更新）
- `/api/update/check` 返回里 `source:"local"`、`updateFile` 指向实际读取的文件
- 正式版 `legado-web` 行为不变，仍从 `TZYLXS/FnReader` 的 Release 检查

## 书城兜底：自动补封面 / 简介 / 评分（3.0.3+）

书架上缺封面、缺简介、缺评分的书，服务端会在后台按站点补全（只填空字段，不覆盖已有数据）：

| 书籍类型 | 数据来源 | 能拿到 |
| --- | --- | --- |
| 出版物（非网文站书源） | 亚马逊 `amazon.com`（书名+作者搜索 → 商品页） | 封面、简介、评分与评价数 |
| 网文（`qidian.com`） | 起点移动版书籍页 | 封面、简介 |
| 网文（`jjwxc.net`） | 晋江移动版书籍页 | 封面、简介（尽力而为） |

使用要点：

- **评分只在「亚马逊书城」和「Kindle 书城」两个主题里显示**（星级 + `4.7 · 17 评分`），其他主题不显示
- 开关：设置 → 阅读 → 「书城兜底」，默认开启；关闭后不再自动抓取
- 触发时机：加书后自动（网文/出版物都试一次）、服务启动后低优先级补 6 本、也可手动触发：

```http
POST /api/books/enrich
{ "url": "<bookUrl>", "force": true }
```

- 结果按「书名+作者」缓存 7 天（失败缓存 6 小时），封面会下载到数据目录 `covers/` 并回写 `/api/covers/xxx`，前端不直连第三方
- 亚马逊会间歇性返回 1.5 KB 的跳转拦截页，服务端会自动重试（最多 5 次）并从搜索卡片兜底取封面/评分
- 第三方站点可能改版、限流或需要登录：抓取失败一律静默，不影响阅读

## 目录解析优先级（3.0.4+）

TOC 解析顺序固定为 **客户端代理最优先**，Python / Java 引擎都排在它后面：

1. 手机端缓存目录（有则用；不完整也会继续问手机）
2. 手机端实时解析（在线设备即用，能过反爬/登录态）
3. Python 引擎（开启且工作模式为「解析」时）
4. 内置 Node 解析
5. 目录规范化：Java 21 引擎（最多等 4 秒，超时直接用 Node 规范化）

配套的非阻塞改动：

- `/api/engine` 的探测最多等 1.5 秒，超时返回 `starting:true`，设置页显示「启动中…」而不是卡死
- 打开/关闭 Java 引擎立即返回（后台拉起 worker），开关不再卡在「Python 启动中」
- Python 引擎开关探测最多 2.5 秒；超时先允许开启，状态后续刷新
- 设置页显示「启动中」后会在 2.5 秒自动刷新一次状态
