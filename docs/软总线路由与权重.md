# 软总线路由与权重系统

> 适用版本：服务端 2.6.17+（2.6.18 修复在途泄漏、隐藏性能分）
> 代码位置：`app/server/src/remote.js`（队列/传输）+ `app/server/src/busweights.js`（权重计算）

软总线负责把「服务端解析不了的任务」交给在线的客户端（手机 App / 调试工具）执行。
本文说明 **任务如何拆分、设备如何打分、任务如何分配**。

---

## 1. 任务分类

| 类 | 任务类型 | 默认由谁处理 |
| --- | --- | --- |
| `book` | `search`、`toc`、`rank` | 高分设备（性能好） |
| `content` | `content`、`ebook-parse`、`ebook-chapter` | 高分设备（性能好） |
| `media` | `cover`、`intro`、`bookinfo` | 低分设备（性能一般） |

- `cover` / `intro` 是 2.6.17 新增的**拆分任务**：书籍详情接口会并行下发这两个任务，
  客户端不支持时会回 `ok:false`，服务端自动回退到 `bookinfo`。
- 分类表定义在 `busweights.js` 的 `TASK_CLASS`，新增任务类型只需在这里补一行。

## 2. 设备隐藏性能分

每台设备在服务端维护一个 **0–100 的隐藏分**（不对客户端/网页暴露）：

| 事件 | 分数变化 |
| --- | --- |
| 初始 | 50 |
| 回传成功 | +4 |
| 回传失败 | −8 |
| 成功但耗时 > 8 秒 | 额外 −2 |
| 上下限 | 0 – 100 |

派生规则：

- `score >= 55` → 高分设备：可领 `book` / `content` / `media`，`book` 并行 2 路，在途上限 **3**
- `score < 55` → 低分设备：同样可领 `book` / `content` / `media`，但 `book`/`content` 只给 **1 路**（0.1.41 起；此前低分设备只能领 `media`，导致 search/toc 全部堆到唯一的高分设备，低分设备分数也永远涨不上来）
- 在线的高分设备数量为 0 时，**自动放开全部任务类**，避免新部署没人领任务
- 调试设备（ID 含 `bus-debug`/`busmon`/`monitor`/`mock`/`fake`/`e2e`/`debug`，
  或名称含「调试/监控/测试机」）不受分类限制，但**回传一律丢弃**

## 3. 任务分配规则

### 3.1 领取即锁定

- `GET /api/m/remote/pending` 返回任务时写入 `dispatchedTo = deviceId`，锁 **30 秒**
- 其它设备在锁定期内看不到该任务
- 锁过期（客户端领了但没回传）→ 其它设备可重新领取
- 任务超时（`waitMs` 到期）自动释放，等待方收到 `timeout`

### 3.2 分类匹配

```text
高分设备候选：book → content → media（按此顺序优先）
低分设备候选：media → book → content（额度更小，参与分担）
调试设备候选：全部（payload.debug 的任务也只给调试设备）
```

### 3.3 在途上限

每台设备同时最多持有 `maxInflight` 个任务（高分 3 / 低分 2），
`pending` 每次只返回剩余名额内的任务；服务端会按“实际锁定在手”的任务重算名额，
避免异常路径导致设备被卡死。

### 3.4 暂停与在线

- 设备超过 60 秒没有心跳视为离线
- `enabled=false` 的设备 `pending` 直接返回空数组，不再派任务
- 网页端「设置 → 软总线」可暂停/恢复设备（`POST /api/bus/toggle`）

### 3.5 结果幂等

- 任务完成后保留 5 分钟完成记录
- 同一 `id` 重复回传：返回 `{"ok":"duplicate"}`，不重复触发业务逻辑
- 非锁定设备的回传会被丢弃（`stale`）
- 调试设备的回传会被丢弃（`ignored`）

## 4. 权重系统模块边界

`busweights.js` 是**纯计算模块**，不碰网络、不碰队列、不递归：

```js
const weights = require('./busweights');

weights.classOf(type)                     // 任务类型 → 类
weights.newDevice(prev, info)             // 新设备初始统计（保留历史分数）
weights.updateScore(dev, ok, ms)          // 回传后更新隐藏分
weights.eligibleClasses(dev, anyHigh)     // 设备可领的任务类
weights.maxInflight(dev)                  // 设备在途上限
weights.sortJobs(jobs, dev, classes)      // 任务优先级排序
weights.hasHighOnline(devices)            // 是否有高分设备在线
weights.summarize(devices, isOnline)      // {highScore, lowScore}
weights.safe(fn, fallback)                // 统一容错包装
```

所有导出函数内部都有 `try/catch`：**权重计算出错只会降级为默认策略，不会抛回总线主流程**，
因此不会因为某台设备数据异常而卡死整个软总线。

### 调参入口

| 参数 | 位置 | 说明 |
| --- | --- | --- |
| `HIGH_SCORE` | `busweights.js` | 高分阈值，默认 55 |
| `HIGH_INFLIGHT` / `LOW_INFLIGHT` | `busweights.js` | 在途上限，默认 3 / 2 |
| `LOCK_MS` | `remote.js` | 领取锁时长，默认 30000 |
| `DONE_TTL` | `remote.js` | 幂等记录保留，默认 5 分钟 |
| `ONLINE_MS` | `remote.js` | 离线判定，默认 60 秒 |

## 5. 观测接口

`GET /api/bus` 返回（**不含**设备分数等内部字段）：

```json
{
  "devices": [
    {"id":"26c92e6d1fd304aa","name":"M2102J2SC","online":true,"idle":2,"handled":12,"enabled":true,"debug":false}
  ],
  "pending": 0,
  "recent": [{"at":1794,"type":"search","ok":true,"by":"…","keys":["books"]}],
  "highScore": 1,
  "lowScore": 2,
  "usage": {"phoneSearch":9,"phoneToc":2,"phoneContent":5,"localToc":0,"localContent":3}
}
```

- `highScore` / `lowScore`：在线设备中高分/低分数量（用于确认路由是否生效）
- `usage`：各类任务实际由手机/本机处理的次数（排查“手机代理没生效”）

## 6. 与旧行为对比

| 行为 | 2.6.16 及以前 | 2.6.17+ |
| --- | --- | --- |
| 任务分配 | 所有设备抢同一队列，重复领取 | 领取即锁定，不重复 |
| 设备差异 | 不区分 | 隐藏分 + 任务类路由 |
| 封面/简介 | 与正文混在 `bookinfo` | 拆成 `cover` / `intro`，派给低分设备 |
| 暂停设备 | 仍会领任务 | 不再派发 |
| 重复回传 | 静默丢弃 | 返回 `duplicate` |
| 权重计算 | 混在 `remote.js` | 独立 `busweights.js`，异常降级 |

## 7. 客户端需要做什么

1. 继续按 `pending` → `result` 流程实现，无需关心分数
2. 支持新类型 `cover` / `intro` 更好（不支持时服务端自动回退 `bookinfo`）
3. 回传时带 `deviceId`（body 或 `X-Device-Id` 头），便于统计与锁定校验
4. 同一任务重复回传无副作用，可安全重试

## 回传数据解析（3.1.1+）

手机端回传的目录数据统一走 `normalizeBusChapters()`：

- 支持直接数组、`{chapters:[...]}`、以及字符串化 JSON（安卓端偶发 double-encode）
- 章节字段兼容 `title|name`、`url|chapterUrl|fileUrl`
- 单遍扫描 + URL 去重，上限 20000 章；超过 1500 章的目录直接 JS 规范化，不再跨进程调用 Python
