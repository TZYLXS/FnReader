# 客户端缓存上传改造指南

面向：要修改 Android 客户端（阅读Pro / 阅读 · Legado 底座）让它把本地缓存推到 FnReader 的开发者。

服务端版本：**FnReader ≥ 1.10.2**（接口 `POST /api/m/cache`，`layout: "legado"`）

---

## 1 整体流程

```
客户端                                     FnReader (NAS)
  │  扫描 book_cache/<书目录>/ 下的 .nb 文件
  │  ├─ 读原文（File.readText()，不做任何处理）
  │  ├─ 读封面（缓存目录里的 cover 或 DB 里的 coverUrl 下载）
  │  ├─ 读图片（<书目录>/images/*）
  │  │
  │  └─ POST /api/m/cache  一次一本 ────────▶ 转码：去标签/去缩进/拆段落
  │                                           原文存 raw/、图片存 images/
  │                                           写 0001 xxx.txt、meta.json
  │                                           登记书架（cachedDir）
  ◀────────────── { ok, dir, chapters, images, bytes }
```

客户端**不做任何文本处理**——去标签、补缩进、拆段落全在服务端完成。

---

## 2 客户端数据在哪

Legado 的缓存根目录：

```kotlin
// io.legado.app.help.book.BookHelp
private val downloadDir: File = appCtx.externalFiles
private const val cacheFolderName = "book_cache"

// 实际路径
/storage/emulated/0/Android/data/<包名>/files/book_cache/
```

每本书一个目录，目录名由 `Book.getFolderName()` 给出（DB 里有缓存，取不到时按规则算）：

```kotlin
fun getFolderNameNoCache(): String =
    name.replace(fileNameRegex, "")
        .let { it.substring(0, min(9, it.length)) + MD5Utils.md5Encode16(bookUrl) }
```

章节文件名：

```kotlin
// BookChapter.getFileName()
String.format("%05d-%s.%s", index, titleMD5, "nb")
// 例：00012-9f86d081884c7d65.nb
```

图片目录：`<书目录>/images/<md5-16(图片url)>.<后缀>`

所以客户端需要的数据：

| 数据 | 来源 |
| --- | --- |
| 书目录路径 | `File(BookHelp.cachePath, book.getFolderName())` |
| 章节列表 | `appDb.bookChapterDao.getChapterList(book.bookUrl)` → `index`/`title`/`url` |
| 章节原文 | `File(书目录, chapter.getFileName()).readText()` |
| 图片 | `File(书目录, "images").listFiles()` |
| 封面 | `book.coverUrl` 下载，或缓存目录里已有的 `cover.jpg` |

## 3 接口约定

### 3.1 请求

```http
POST {serverUrl}/api/m/cache
Content-Type: application/json; charset=utf-8
X-Api-Token: {token}
```

```json
{
  "layout": "legado",
  "book": {
    "bookUrl": "https://www.example.com/book/123",
    "name": "凡人修仙传",
    "author": "忘语",
    "origin": "https://www.example.com",
    "originName": "示例源",
    "intro": "简介（可空）",
    "totalChapterNum": 2400,
    "durChapterIndex": 128
  },
  "coverData": "iVBORw0KGgoAAAANSUhEUg...",
  "coverMime": "image/jpeg",
  "chapters": [
    {
      "index": 12,
      "title": "第十二章 浓雾",
      "url": "https://www.example.com/chapter/12",
      "file": "00012-9f86d081884c7d65.nb",
      "raw": "　　浓雾在窗外翻滚，世界都消失在了雾的彼端。\n　　他转过身，看到了<img src=\"https://cdn.example.com/1.jpg\">挂在墙上。"
    }
  ],
  "images": [
    { "name": "9f86d081884c7d65.jpg", "data": "/9j/4AAQSkZJRgABAQ..." }
  ]
}
```

### 3.2 字段表

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `layout` | string | ✅ | 固定 `"legado"` |
| `book.bookUrl` | string | ✅ | 书的唯一标识，服务端按它去重 |
| `book.name` | string | ✅ | 书名，用于建目录 |
| `book.author` | string |  | 作者 |
| `book.origin` | string |  | 书源地址（保留来源） |
| `book.originName` | string |  | 书源名称 |
| `book.intro` | string |  | 简介，服务端截断到 1000 字 |
| `book.durChapterIndex` | int |  | 当前阅读进度 |
| `coverData` | string(base64) |  | 封面二进制；**不要带 `data:` 前缀也行**（服务端会剥） |
| `coverMime` | string |  | `image/jpeg` / `image/png` / `image/webp` |
| `chapters[].index` | int |  | 客户端章节序号（仅参考，服务端按数组顺序重排） |
| `chapters[].title` | string |  | 章节标题 |
| `chapters[].url` | string |  | 章节地址 |
| `chapters[].file` | string |  | **客户端缓存文件名**，原样保存到 `raw/` |
| `chapters[].raw` | string |  | **文件原文**，不要预处理 |
| `images[].name` | string |  | 图片文件名 |
| `images[].data` | string(base64) |  | 图片二进制 |

### 3.3 响应

```json
{
  "ok": true,
  "layout": "legado",
  "dir": "/vol3/1000/DownLoad/cache/凡人修仙传",
  "chapters": 2400,
  "withText": 2398,
  "images": 12,
  "bytes": 18632142,
  "cover": "http://192.168.5.114:1122/api/covers/b0ca563fe607eede.png"
}
```

| 字段 | 说明 |
| --- | --- |
| `dir` | 服务端落盘目录（排查用） |
| `withText` | 真正有正文的章节数（抓取失败的章节可能没内容） |
| `bytes` | 写入的字节数 |

## 4 客户端实现（Kotlin）

### 4.1 扫描缓存

```kotlin
data class CacheUpload(val book: Book, val chapters: List<Pair<BookChapter, String>>,
                       val images: List<File>, val cover: File?)

fun scanCache(book: Book): CacheUpload? {
    val dir = File(BookHelp.cachePath, book.getFolderName())
    if (!dir.exists()) return null

    val chapters = appDb.bookChapterDao.getChapterList(book.bookUrl).mapNotNull { ch ->
        val f = File(dir, ch.getFileName())
        if (f.exists()) ch to f.readText() else null   // 原文，不处理
    }
    val images = File(dir, "images").listFiles()?.toList() ?: emptyList()
    val cover = dir.listFiles()?.firstOrNull { it.name.startsWith("cover.") }
    return CacheUpload(book, chapters, images, cover)
}
```

### 4.2 构建 JSON

```kotlin
private fun File.b64(): String = Base64.encodeToString(readBytes(), Base64.NO_WRAP)

fun CacheUpload.toJson(): JSONObject = JSONObject().apply {
    put("layout", "legado")
    put("book", JSONObject().apply {
        put("bookUrl", book.bookUrl)
        put("name", book.name)
        put("author", book.author)
        put("origin", book.origin)
        put("originName", book.originName)
        put("intro", book.intro ?: "")
        put("totalChapterNum", chapters.size)
        put("durChapterIndex", book.durChapterIndex)
    })
    cover?.let {
        put("coverData", it.b64())
        put("coverMime", if (it.extension.equals("png", true)) "image/png" else "image/jpeg")
    }
    put("chapters", JSONArray().apply {
        chapters.forEachIndexed { i, (ch, raw) ->
            put(JSONObject().apply {
                put("index", ch.index)
                put("title", ch.title)
                put("url", ch.url)
                put("file", ch.getFileName())
                put("raw", raw)          // ← 原始文本
            })
        }
    })
    put("images", JSONArray().apply {
        images.forEach { img ->
            put(JSONObject().apply {
                put("name", img.name)
                put("data", img.b64())
            })
        }
    })
}
```

### 4.3 上传（OkHttp）

```kotlin
suspend fun uploadCache(serverUrl: String, token: String, payload: JSONObject): Result<JSONObject> =
    withContext(Dispatchers.IO) {
        runCatching {
            val body = payload.toString().toRequestBody("application/json; charset=utf-8".toMediaType())
            val req = Request.Builder()
                .url("$serverUrl/api/m/cache")
                .addHeader("X-Api-Token", token)
                .post(body)
                .build()
            OkHttpClient.Builder()
                .connectTimeout(10, TimeUnit.SECONDS)
                .writeTimeout(120, TimeUnit.SECONDS)   // 整本书可能几十 MB
                .readTimeout(120, TimeUnit.SECONDS)
                .build()
                .newCall(req).execute().use { resp ->
                    val text = resp.body?.string().orEmpty()
                    if (!resp.isSuccessful) error("HTTP ${resp.code}: $text")
                    JSONObject(text)
                }
        }
    }
```

### 4.4 触发时机

| 时机 | 建议 |
| --- | --- |
| 用户点「同步到飞牛」 | 立即上传，进度条显示章节数 |
| 批量同步 | 串行，一本一个请求，避免 NAS 带宽打满 |
| 缓存下载完成（可选） | 自动上传，加开关 |

失败重试：指数退避 2/4/8/16/32 秒，5 次后标记失败并在书架角标提示。

## 5 大书怎么办

单次请求体上限 **32 MB**。整本 2000+ 章通常 10–30 MB，多数能一次推完。

超过限制时的处理：

1. **优先**：只推「已缓存」的章节（`chapters` 里只放存在的文件），通常远小于全书
2. 分批：先推前 500 章，等服务端返回后再推下一批（**注意**：目前每批会新建一个目录，
   分批会产生 `书名 (2)`、`书名 (3)`，建议等增量参数上线后再用）

---

## 6 服务端怎么处理

1. 目录：`<下载目录>/cache/<书名>/`（重名自动 `(2)`）
2. 原文：`raw/<客户端 fileName>`（原样，不转码）
3. 转码：`raw` → 去 `<img>`（换成 `[图片]`）、去段首 `　　`、按行拆段、段间空行 → `0001 标题.txt`
4. 图片：`images/<name>`
5. 封面：公共 `covers/`，回写书架 `coverUrl`
6. 书架：写 `chapters[].file` + `cachedDir`，之后 `/api/content` 直接读本地文件

## 7 怎么验证

### 7.1 命令行发一本

```bash
curl -X POST "http://<NAS_IP>:1122/api/m/cache" \
  -H "Content-Type: application/json; charset=utf-8" \
  -H "X-Api-Token: <令牌>" \
  --data-binary @payload.json
```

期望：

```json
{"ok":true,"layout":"legado","dir":"/vol3/1000/DownLoad/cache/凡人修仙传",
 "chapters":2,"withText":2,"images":1,"bytes":484,"cover":"http://…/api/covers/…png"}
```

### 7.2 看文件

```bash
ls -R "/vol3/1000/DownLoad/cache/凡人修仙传"
```

### 7.3 阅读

```
GET /api/content?url=<bookUrl>&index=0
```

返回 `paragraphs`，且 `[图片]` 出现在图片位置，说明转码成功。

## 8 错误排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 401 | 令牌错误 | 设置页「手机接入」复制最新令牌 |
| 400 `缺少 book.bookUrl` | body 结构不对 | 检查是不是把 book 平铺了 |
| 章节有目录无正文（`withText` < `chapters`） | `raw` 为空 | 客户端要传文件原文，不是空串 |
| 正文里出现 `&lt;p&gt;` | 客户端做了 HTML 转义 | 别转义，原样传 |
| 中文乱码 | 请求体非 UTF-8 | 明确 `charset=utf-8` |
| 图片显示 `[图片]` 但没有文件 | 图片没传或 base64 坏 | 检查 `images[]` |

## 9 自测清单

- [ ] 单章短书能同步，`withText == chapters`
- [ ] 含图片的章节：`[图片]` 位置正确，`images/` 里有文件
- [ ] 封面同步后书架显示新封面
- [ ] 断网时同步失败并进入重试队列
- [ ] 同一本推两次：服务端生成 `书名 (2)`（知道这个行为）
- [ ] 2000 章的书能在 120 秒内传完（否则调大 writeTimeout 或改分批）
- [ ] 推完后网页端打开该书，目录与正文正常、无乱码
