# 简介补全接口（给 APK 客户端）

面向：阅读Pro / 阅读（Legado 底座）客户端开发者。

背景：服务端抓简介这条路是残的——起点详情页返回 202 反爬挑战，晋江书名用字体混淆。
客户端有登录态和 WebView，**能拿到真简介**。所以约定一个任务：服务端缺简介时问客户端，客户端回传。

服务端版本：**FnReader ≥ 2.0.0**

---

## 1 时序

```
服务端                                     客户端（App）
  │ 用户在网页点开详情 / 请求 /api/intro
  │ 本地书源 + 晋江都拿不到 intro
  │
  ├─ 建任务 bookinfo ──────────────────────▶ 轮询 /api/m/remote/pending 领到
  │                                            │ 用 Legado 详情规则抓 bookUrl
  │                                            │ 组装 {intro, author, coverUrl, …}
  ◀──────────────────── POST /api/m/remote/result
  │
  ├─ 写回书架 book.intro / coverUrl
  └─ 响应网页，带 "via": "phone"
```

超时 **10 秒**，拿不到就按原样返回，不影响页面打开。

---

## 2 任务格式

服务端下发的任务（客户端在 `/api/m/remote/pending` 里会看到）：

```json
{
  "id": "53d126dc722f",
  "type": "bookinfo",
  "payload": {
    "bookUrl": "http://www.feisuwx.org/book/274/274864/index.html",
    "source": "https://www.aixiawx.com/",
    "name": "黎明之剑",
    "author": "远瞳"
  },
  "age": 1200
}
```

| 字段 | 说明 |
| --- | --- |
| `type` | 固定 `bookinfo` |
| `payload.bookUrl` | 书籍详情页地址（**必用**，抓这个页面） |
| `payload.source` | 书源地址，用于找 `BookSource`；可能为空 |
| `payload.name` / `author` | 书名作者，用于在书源里反查 |

---

## 3 回传格式

```http
POST /api/m/remote/result
X-Api-Token: <令牌>
Content-Type: application/json; charset=utf-8

{
  "id": "53d126dc722f",
  "deviceId": "26c92e6d1fd304aa",
  "ok": true,
  "data": {
    "intro": "高文穿越到一个即将被魔潮吞没的世界……",
    "author": "远瞳",
    "coverUrl": "https://…/cover.jpg",
    "kind": "奇幻",
    "wordCount": "500万字",
    "lastChapter": "第1594章 8：05",
    "totalChapterNum": 1594
  }
}
```

字段**全部可选**，拿得到就给，拿不到的省略（不要传空字符串以外的占位值）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `intro` | string | 书籍简介，最重要；可含换行 |
| `author` | string | 作者 |
| `coverUrl` | string | 封面绝对地址 |
| `kind` | string | 分类/状态，如「奇幻」「连载中」 |
| `wordCount` | string | 字数，如「500万字」 |
| `lastChapter` | string | 最新章节标题 |
| `totalChapterNum` | int | 总章节数 |

失败时回：

```json
{ "id": "…", "ok": false, "error": "详情页需要登录" }
```

## 4 客户端实现（Kotlin）

### 4.1 在轮询循环里加一个分支

```kotlin
when (job.type) {
    "search"   -> handleSearch(job)
    "toc"      -> handleToc(job)
    "content"  -> handleContent(job)
    "bookinfo" -> handleBookInfo(job)   // ← 新增
}
```

### 4.2 用 Legado 现有能力抓详情

```kotlin
private suspend fun handleBookInfo(job: RemoteJob) {
    val payload = job.payload
    val bookUrl = payload.optString("bookUrl")
    val sourceUrl = payload.optString("source")

    // 1) 优先用任务里带的源；找不到就按 host 反查一个
    val source = appDb.bookSourceDao.getBookSource(sourceUrl)
        ?: appDb.bookSourceDao.all.firstOrNull { it.bookSourceUrl.host == bookUrl.host }

    if (source == null) {
        postResult(job.id, ok = false, error = "没有匹配的书源")
        return
    }

    // 2) 用临时的 Book 对象跑 ruleBookInfo
    val book = Book(
        bookUrl = bookUrl,
        origin = source.bookSourceUrl,
        name = payload.optString("name"),
        author = payload.optString("author")
    )

    val info = try {
        WebBook.getBookInfoAwait(source, book)
    } catch (e: Exception) {
        postResult(job.id, ok = false, error = e.localizedMessage ?: "抓取失败")
        return
    }

    // 3) 只回非空字段
    val data = JSONObject().apply {
        info.intro?.takeIf { it.isNotBlank() }?.let { put("intro", it) }
        info.author?.takeIf { it.isNotBlank() }?.let { put("author", it) }
        info.coverUrl?.takeIf { it.isNotBlank() }?.let { put("coverUrl", it) }
        info.kind?.takeIf { it.isNotBlank() }?.let { put("kind", it) }
        info.wordCount?.takeIf { it.isNotBlank() }?.let { put("wordCount", it) }
        info.latestChapterTitle?.takeIf { it.isNotBlank() }?.let { put("lastChapter", it) }
        if (info.totalChapterNum > 0) put("totalChapterNum", info.totalChapterNum)
    }
    postResult(job.id, ok = true, data = data)
}
```

### 4.3 回传

```kotlin
private suspend fun postResult(id: String, ok: Boolean, data: JSONObject? = null, error: String? = null) {
    val body = JSONObject().apply {
        put("id", id)
        put("deviceId", deviceId())        // 软总线设备 id
        put("ok", ok)
        if (ok && data != null) put("data", data) else put("error", error ?: "failed")
    }
    withContext(Dispatchers.IO) {
        okhttp.newCall(
            Request.Builder()
                .url("$serverUrl/api/m/remote/result")
                .addHeader("X-Api-Token", token)
                .post(body.toString().toRequestBody(JSON))
                .build()
        ).execute().close()
    }
}
```

## 5 服务端什么时候会问

| 入口 | 条件 |
| --- | --- |
| `GET /api/intro?name=&author=&url=` | 传了 `url`，且本地书源/晋江都没拿到 intro |
| `GET /api/detail?url=&origin=` | 返回的 `book.intro` 或 `book.coverUrl` 为空 |

命中后：

- 响应里带 `"via": "phone"`
- 结果写回书架（`intro`/`coverUrl`/`author`/`kind`/`wordCount`/`lastChapter`），**只补空字段**

## 6 怎么自测

### 6.1 命令行验证服务端会发任务

```bash
# 终端 A：模拟客户端领任务（拿到 job 打印出来即可，不一定要回结果）
curl -N "http://<NAS>:1122/api/m/remote/pending?token=<令牌>&id=test&name=test&wait=15000"

# 终端 B：触发服务端提问（换成一本没有简介的书）
curl "http://<NAS>:1122/api/detail?url=<bookUrl>&origin=<书源地址>"
```

终端 A 应该在 1 秒内打印出 `type: "bookinfo"` 的任务。

### 6.2 验证整条链路

```bash
curl -X POST "http://<NAS>:1122/api/m/remote/result" \
  -H "X-Api-Token: <令牌>" -H "Content-Type: application/json" \
  -d '{"id":"<任务id>","ok":true,"data":{"intro":"测试简介","author":"测试作者"}}'

curl "http://<NAS>:1122/api/detail?url=<bookUrl>"
# 期望：book.intro == "测试简介"，响应里 via == "phone"
```

### 6.3 看书架是否写回

```bash
curl "http://<NAS>:1122/api/books" | grep -o '"intro":"[^"]*"'
```

## 7 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 服务端不问手机 | 本地书源已经拿到简介 | 正常；加 `&force=1` 强制重查 |
| 一直超时 | 客户端没实现 `bookinfo` 分支 | 检查 `when (job.type)` 是否有该分支 |
| 回传后网页还是没有 | `id` 对不上 / 已超时（10 秒） | 确认 `id` 用的是任务里的值 |
| intro 是 HTML | 详情规则取到了富文本 | 客户端先 `HtmlFormatter.formatKeepImg` 去标签再回传 |
| 中文变乱码 | 请求体不是 UTF-8 | 明确 `charset=utf-8` |

## 8 客户端实测反馈（2026-11-10，v2.0.0 模拟器）

实测通过的部分：

| 任务 | 结果 |
| --- | --- |
| `bookinfo` | ✅ 约 0.7–1.0 s 返回 `intro/author/coverUrl/kind/lastChapter` |
| `toc` | ✅ 1.2 s 返回 chapters |
| `content` | ✅ 91 段 |
| `search` | ✅ 50 条结果 |
| `/api/detail` | ✅ 首次 `via: "phone"`，结果写回书架 |

遇到的两类失败（都返回了 `ok:false`，服务端能正常降级）：

| 返回 | 含义 | 建议 |
| --- | --- | --- |
| `没有匹配的书源：http://…` | 该 URL 在本机书源里找不到 | 先用 `source` 精确匹配，再按 host 匹配；都失败时**退化为按书名在本机全部书源里搜一次**，取第一条的详情 |
| `本机没有这个书源：http://…` | 同上（search 任务） | 同上 |

名字兜底伪代码：

```kotlin
val info = when {
    source != null -> WebBook.getBookInfoAwait(source, book)
    else -> {
        // 本机没有这个源：按书名搜一轮，取第一个能抓详情的
        appDb.bookSourceDao.all.asSequence()
            .mapNotNull { src -> runCatching { WebBook.getBookInfoAwait(src, book) }.getOrNull() }
            .firstOrNull { !it.intro.isNullOrBlank() }
    }
}
```

这样即使服务端和客户端的书源集合不一致，简介也有很高概率补上。
