# 本地电子书解析引擎接入规范（Text Parsing Engine）

> 适用版本：FnReader 2.2.0+
> 引擎来源：[TZYLXS/Text-Parsing-Engine](https://github.com/TZYLXS/Text-Parsing-Engine)（`server/ebook/*`）
> 本文是**接口与实现规范**，改代码或对接客户端时以本文为准。

---

## 1 定位与边界

引擎只做两件事：把本地电子书变成 `fnreader.ebook.v1` JSON，把 JSON 渲染成目录/正文。

| 格式 | 服务端 | 手机端 |
| --- | --- | --- |
| EPUB / MOBI / PRC / AZW | 兜底解析 | **优先**由在线客户端解析回传 |
| PDF | 文本层解析 | 不派发 |
| TXT | 解析 | 不派发 |

约束：

- 书 URL 固定为 `ebook://<sha1>`（40 位小写 sha1，不随解析来源变化）
- 原文件只下发一次给客户端，客户端回传 JSON 分片；服务端落盘后不再解析原文件
- 渲染只读 `book.json` 与 `ch/*.json`
- 服务端不新增 npm 依赖（只用到已有的 `cheerio`）

---

## 2 数据流

```
扫描目录（ebookDir）
  └─ 命中 epub/mobi/pdf/txt
       ├─ 计算 sha1 → 复制原文件到 <dataDir>/ebook/files/<sha1>.<ext>
       ├─ 登记 index.json（status=discovered）
       └─ bus.dispatch
            ├─ PDF/TXT ───────────────────────────────→ 本地解析（server）
            ├─ EPUB/MOBI + 有在线设备 → remote.create('ebook-parse')
            │     ├─ GET  /api/m/ebook/file/<sha1>     整本下载（支持 Range）
            │     ├─ POST /api/m/ebook/part?sha1&seq&total
            │     └─ POST /api/m/remote/result
            └─ 无设备 / 迟迟不开工 / 掉线 ─────────────→ 本地兜底（server）
```

状态机（`index.json` 每条的 `status`）：

```
discovered → queued → partial → complete
     └──────────────→ parsing（本地兜底）
     └──────────────→ failed（drm / corrupt / unsupported / kf8-unsupported / EACCES…）
```

## 3 配置项

写在 `<dataDir>/config.json`（`DEFAULT_CONFIG` 已内置默认值，可不填）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `ebookEnabled` | `true` | 总开关；false 时不扫描不派发 |
| `ebookDir` | 空 | 扫描目录；空则用 `<downloadDir>/ebook` |
| `ebookScanSec` | `60` | 定时扫描间隔（秒） |
| `ebookScanDepth` | `3` | 目录递归深度 |
| `ebookMaxMB` | `512` | 单本大小上限 |
| `ebookFallbackEnabled` | `true` | 客户端迟迟不回时是否本地兜底 |
| `ebookFallbackAfterMin` | `10` | 派发后多少分钟无进展就兜底 |
| `ebookOfflineGraceSec` | `120` | 客户端掉线宽限（秒） |
| `ebookLocalConcurrency` | `2` | 本地解析并发 |
| `ebookJobTtlMs` | `600000` | `ebook-parse` 任务存活时间 |

> `ebookDir` **不要**指向 `<dataDir>/ebook`（解析产物目录），否则会把自己的副本当新书扫到。

## 4 服务端接口

### 4.1 管理接口（网页/运维，无令牌）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/ebook/list` | `{dir, count, books:[{sha1,name,format,size,status,source,chapters,parts,error,sourcePath,file}]}` |
| POST | `/api/ebook/scan` | 立即扫一次，返回 `{root,found,added,skipped,errors}` |
| POST | `/api/ebook/reparse` | body `{sha1}`：清 `ch/`、`parts/`，状态回 `discovered` 再派发 |

### 4.2 客户端接口（需 `X-Api-Token`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/m/ebook/file/<sha1>` | 整本下载。支持 `Range: bytes=start-`，越界 416，成功 206/200；`Content-Type` 按格式 |
| POST | `/api/m/ebook/part?sha1=&seq=&total=` | 上传分片。明文 JSON ≤8 MB；支持 `Content-Encoding: gzip`（解压后 ≤20 MB）；成功 `{ok,chapters,total,received,complete}` |
| GET | `/api/m/ebook/parts?sha1=` | 断点查询 `{sha1,total,received,complete,status,parts:[seq]}` |

错误码：

| 场景 | 状态码 | 说明 |
| --- | --- | --- |
| token 缺失/错误 | 401 | 与 `/api/m/*` 一致 |
| sha1 非法 | 400 | 非 40 位十六进制 |
| 文件不存在 | 404 | 登记表无此 sha1 或原文件被删 |
| 分片超限 | 413 | 8 MB / 20 MB 限制 |
| `schema` 不匹配 | 400 | 分片被整体拒绝 |
| `sha1` 不一致 | 409 | 分片属于别的书 |
| gzip 解压失败 | 400 | — |

### 4.3 渲染接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/toc?url=ebook://<sha1>` | 返回 `{chapters:[{index,title,url,level}], name, meta, total, status, source, via:"ebook-json"}` |
| GET | `/api/content?url=ebook://<sha1>&index=N` | 返回 `{title,index,total,next,prev,paragraphs[],via:"ebook-json"}`；越界 404 |

渲染分支在 `/api/toc`、`/api/content` 最前面拦截 `ebook://`，**不会**落到书源解析逻辑。

### 4.4 软总线任务

| 项 | 值 |
| --- | --- |
| type | `ebook-parse` |
| 白名单 | `/api/remote/job` 已加入；等待上限 **240 s**（其他类型 60 s） |
| payload | 见 §5.1 |
| 结果 | `{chapters, parts, chars}`；`ok:false` 时 `error` 为错误码 |

### 4.5 启动行为

`server.listen` 之后：

```js
ebookScan.start(ctx, (config.ebookScanSec || 60) * 1000);
ebookBus.startWatchdog(ctx);
```

日志会打印 `本地电子书引擎已启动，目录: <ebookDir>` 与 `[ebook] 扫描完成 … 发现=N 新增=N`。

## 5 协议契约 `fnreader.ebook.v1`

### 5.1 任务 payload（服务端 → 手机）

```json
{
  "sha1": "4d90f9658cb18d3e6edebe7c854dccec2bcaef34",
  "name": "书名",
  "format": "epub",
  "size": 1048576,
  "fileUrl": "/api/m/ebook/file/4d90f9…",
  "token": "<本次令牌>",
  "schema": "fnreader.ebook.v1",
  "partMaxBytes": 4194304
}
```

### 5.2 part 0（清单）

```json
{
  "schema": "fnreader.ebook.v1",
  "sha1": "4d90f9…",
  "format": "epub",
  "name": "书名",
  "meta": {"title":"书名","author":"","language":"zh","publisher":"","publishedAt":"","isbn":"","description":""},
  "toc": [{"id":"ch0001","title":"第一章","level":1,"index":0}],
  "stats": {"chapters":1,"chars":2400,"parts":1}
}
```

### 5.3 part N（正文）

```json
{
  "schema": "fnreader.ebook.v1",
  "sha1": "4d90f9…",
  "seq": 1,
  "total": 2,
  "chapters": [
    {"index":0,"id":"ch0001","title":"第一章",
     "paragraphs":[{"k":"p","t":"正文"},{"k":"quote","t":"引文"},{"k":"hr","t":""}]}
  ]
}
```

约定：

- `schema` 必须完全相等；`sha1` 必须与任务一致
- `index` 全书连续、从 0 开始，与 `toc.index` 对齐
- `k` 仅允许 `p` / `h1`~`h6` / `quote` / `hr` / `img`
- `t` 是去标签纯文本，空段丢弃；`hr` 可为空
- 每片建议 ≤4 MB，按章节边界切，不拆章
- `total = 1 + 正文片数`（part 0 也算一片）

---

### 5.4 toc-only（仅目录先行）

客户端本地已有完整目录时，可以**只回传 part0**，正文按需补：

```json
{
  "schema": "fnreader.ebook.v1",
  "sha1": "…",
  "format": "epub",
  "name": "书名",
  "meta": {…},
  "toc": [{"id":"ch0001","title":"第一章","level":1,"index":0}],
  "stats": {"chapters":120,"chars":0,"parts":1},
  "tocOnly": true
}
```

约束与效果：

- `tocOnly:true` **仅在 `seq=0 && total=1` 时生效**，其它组合按旧逻辑处理
- 落库状态为 `toc-only`（**不是** `complete`），`stats.parts=0`、`entry.totalParts=0`
- 书架立即可见（`localEbook.status='toc-only'`），`/api/toc` 直接返回目录与章数
- **不参与 watchdog 与本地兜底**：`bus.dispatch` 跳过 `toc-only`，宽限期到了也不会被 Python 重解析覆盖
- `part0` 只能传一次：已有 book.json 与分片记录时重传返回 `409 {"code":"toc-locked"}`，避免新旧目录串章
- 之后若收到 `seq>0` 正文分片，会自动退出 `toc-only`（状态转 `partial`/`complete`）

### 5.5 单章按需回传

`/api/content` 取不到正文且书处于 `toc-only` / `partial` 时，返回 **200 + needChapter**（不是 404）：

```json
{"needChapter": 5, "sha1": "…", "status": "toc-only", "via": "ebook-local-miss"}
```

客户端据此推送单章：

```http
POST /api/m/ebook/chapter?sha1=<sha1>&index=<index>
X-Api-Token: <token>
{"schema":"fnreader.ebook.v1","sha1":"…","index":5,"paragraphs":[{"k":"p","t":"正文"}]}

→ {"ok":true,"index":5,"chapters":120}
```

校验：`sha1` 40 位 hex、`index` 在目录范围内、`paragraphs` 非空、`k` 限 `p/h1~h6/quote/hr/img`。
错误码沿用分片接口：`sha1` → 409、`too-large` → 413、其余 400。

> 该接口是**客户端主动推**，不走软总线 `remote.create`，不需要任务类型白名单。

### 5.6 状态与兜底的关系

| 状态 | 扫描会重派发 | watchdog 兜底 | 书架可见 | `/api/content` |
| --- | --- | --- | --- | --- |
| `discovered` | 会 | 否 | 否 | 404 |
| `toc-only` | **否** | **否** | 是 | 200 + needChapter |
| `partial` | 否 | 是（掉线宽限后）| 是 | 有章则正文，无章 needChapter |
| `complete` | 否 | 否 | 是 | 正文 |

## 6 存储布局

```
<dataDir>/ebook/
  index.json                 登记表（数组）
  files/<sha1>.<ext>         原文件副本（下发用，复制后 chmod 644）
  books/<sha1>/book.json     schema/meta/toc/stats/source/status
  books/<sha1>/ch/0000.json  章节正文
  books/<sha1>/parts/0000.done  已收分片标记
```

---

## 7 实现要点与坑位

1. **20 秒保护**：文件 `mtime` 距现在 <20 s 时跳过，避免把正在拷贝的书当完整文件。
2. **排除自建目录**：扫描时跳过 `<dataDir>/ebook/files`、`<dataDir>/ebook/books`。
3. **复制后放开读权限**：部分卷/ACL 复制出来是 `0000`，解析会 `EACCES`；`scan.js` 复制后统一 `chmod 644`（本次接入修复）。
4. **长任务单独 TTL**：`remote.create(type, payload, {waitMs, ttlMs})`，`ebook-parse` 用 600 s；
   看门狗与兜底通过 `remote.abandon(id)` 撤销。
5. **不要重解析**：渲染只读 JSON；`books/<sha1>/ch/*` 缺失说明解析未完成（返回 404）。
6. **权限**：扫描目录必须对 `legado` 用户可读；NAS 上的共享文件夹要先 `chown legado` 或授权。

## 10 本地电子书优先：跳过客户端网文同步

**规则**：客户端同步缓存时（`POST /api/m/cache`），服务端先用书名去本地电子书登记表里匹配；
命中则**整本跳过**，不写 `cache/`、不落 `.nb`，直接返回：

```json
{"ok":true,"skipped":true,"reason":"local-ebook","message":"本地已有同名电子书，跳过客户端同步",
 "local":{"sha1":"4d90f9…","name":"黎明之剑","format":"txt","status":"complete"}}
```

匹配规则（`localEbookByName`）：

1. 书名归一化：去掉《》「」【】括号与所有空白，转小写；
2. 先找完全相等；
3. 没有再找「包含」关系，且较短一侧长度 ≥2（避免「剑」这种单字误命中）。

客户端处理建议：收到 `skipped:true` 就把这本书标记为「由 NAS 本地提供」，不再重复上传。

**关闭方式**：请求体带 `skipIfLocal:false` 可以强制走原同步流程。

## 11 客户端只有 TXT：同步 TXT 而不是 `.nb`

客户端如果手里只有 TXT（没有缓存正文），不要再传 `.nb`，改为：

```json
POST /api/m/cache
{
  "format": "txt",
  "text": "第一章 …\n　　正文…",
  "book": {"bookUrl":"…","name":"黎明之剑","author":"…"},
  "skipIfLocal": false
}
```

服务端行为：

1. 不创建 `raw/*.nb`；
2. `format === "txt"` 且 `text` 存在时，调用**本地 Python 引擎** `legado_bridge.py txt` 分章：
   - 按 `第X章 / 第X回 / 第X卷 / Chapter N` 切分（行长度 ≤40 才算标题，避免正文误判）；
   - 返回 `{name, chapters:[{index,title,paragraphs[]}], chars}`；
3. 分章结果按普通缓存章节写入 `<下载目录>/cache/<书名>/0001 标题.txt`；
4. 响应带 `"via":"local-txt"`（`.nb` 路径为 `"via":"legado"`）。

> Python 引擎不可用时返回 502 `本地 TXT 解析失败：…`，不会静默降级成乱码正文。

## 13 解析模式开关（2.2.2 起）

设置 → 下载 → **电子书解析**，三档（默认 `proxy`）：

| 模式 | 配置值 | EPUB/MOBI 行为 | PDF/TXT |
| --- | --- | --- | --- |
| 代理解析（默认） | `proxy` | 有在线手机就派 `ebook-parse`，超时/离线本地兜底 | 本机解析 |
| 仅本机解析 | `local` | 不派手机，直接本机解析 | 本机解析 |
| 关闭 | `off` | 不扫描、不派发（已入库的书仍可读） | 不扫描 |

接口：

```http
GET  /api/ebook/settings
     → {mode:"proxy", enabled:true, dir:"/vol4/1000/Ebook/ebook", scanSec:60,
        local:0, device:1, total:1}

POST /api/ebook/settings {"mode":"local"}   // proxy | local | off
     → {ok:true, mode:"local", enabled:true}
```

实现要点：

- `ebookMode` 存在 `config.json`；`off` 时同时把 `ebookEnabled` 置 false 并跳过启动扫描；
- `bus.dispatch` 开头判定模式：`off` 直接 return，`local` 无条件 `enqueueLocal(reason='local-mode')`；
- 模式改动**立即生效**，不需要重启（扫描仍按 `ebookScanSec` 周期跑）。

## 14 本地副本挂载与书架联动（2.2.4 起，替代 2.2.3 的破坏性改写）

扫描完成后服务端做两件事，**都不动原书源与 `.nb` 缓存**：

### 14.1 扫描到的电子书直接进书架

对每本 `status=complete/partial` 且书架里还没有的电子书，新建书架条目：

```
bookUrl = ebook://<sha1>   origin = local-ebook   originName = 本地电子书
chapters = 取自 ebook 目录   contentSource = local
```

书架里同一 `ebook://` 已存在则跳过，避免重复。

### 14.2 与书架同名书：挂本地副本，不改 URL

若书架上已有同名书（书名归一化后完全相等），给它加两个字段：

```json
"localEbook": {"sha1":"62d8c3c7…","format":"txt","name":"超时空犯罪集团","status":"complete"},
"contentSource": "local"
```

- `bookUrl`、`origin`、`cachedDir`、`.nb` 缓存**全部保留**
- 默认 `contentSource=local`：`/api/toc`、`/api/content` 读本地副本（`via=ebook-json`）
- 阅读页顶栏出现切换按钮（`本` / `网`）：点一下在「本地副本 / 网文源」之间切换
- 切换接口：

```http
POST /api/books/content-source {"url":"<bookUrl>","source":"local"|"source"}
     → {ok:true, source:"source", localEbook:{…}}
```

- 切回 `source` 时走原来的书源/缓存链路，章节数与网文源一致

### 14.3 TXT 由本地 Python 引擎分章

本地 TXT 在挂载前会调 `legado_bridge.py txt` 分章一次（结果写进 `ebook/books/<sha1>/`，`parsedBy=python`），
之后 `/api/toc`、`/api/content` 直读 JSON，不在请求里重复解析。

### 14.4 实测（2026-11-15，正式版 2.2.4）

```
扫描：/vol4/1000/Ebook/ebook → found=1
书架：超时空犯罪集团 | http://www.3yt.info/Book/1910/index.html | contentSource=local
      localEbook={sha1:62d8c3c7…, format:txt}
GET /api/toc（默认）      → 695 章 via=ebook-json
POST content-source source → GET /api/toc → 693 章（网文源）
POST content-source local  → GET /api/toc → 695 章（本地 TXT）
```

> 2.2.3 曾经把书架条目的 `bookUrl` 直接改成 `ebook://`（破坏性），2.2.4 已改为上面的挂载式方案。

```
GET /api/content?index=0      → paragraphs:["正式版按需补的第一章"], via=ebook-json
```

两个环境测试后均已清理（删除测试书、文件与 index 条目，解析模式恢复 `proxy`）。

### 15.3 历史结论（保留）

- 目录自动创建：干净配置启动后 3–8 秒内创建 `<downloadDir>/ebook`（`scan.js` 的 `mkdir recursive`）
- 同名书挂载：不改 `bookUrl`、不清 `cachedDir`，只加 `localEbook` + `contentSource`
- 2.2.3 的「直接改 bookUrl 为 ebook://」已被 2.2.4 的挂载式方案取代

## 16 PDF 文本层：Ghostscript 兜底（2.3.2 起）

内置的 PDF 抽取是轻量实现（解 Flate + 取 `Tj/TJ`），对**嵌入 CID 字体**的中文 PDF 会出现乱码
（典型表现：`¶åÔKç«îÝä¸¥À…` 这种 Latin-1 噪声）。

处理策略：

1. 先按内置解析取文本；
2. 用 `looksGarbled()` 判定乱码（CJK 占比 <3% 且高位字符 >25%，或控制字符 >5%）；
3. 命中则调用系统 **Ghostscript** 的 `txtwrite` 重新抽取：

   ```bash
   gs -q -dNOPAUSE -dBATCH -sDEVICE=txtwrite -sOutputFile=- <file.pdf>
   ```

4. gs 结果仍然乱码 / gs 不存在 → 抛 `font-encoding`，前端提示「PDF 使用嵌入字体且缺少可解映射」。

行为变化：

| 场景 | 之前 | 现在 |
| --- | --- | --- |
| 普通文字版 PDF | 正常 | 正常 |
| CID 嵌入字体中文 PDF | 正文乱码 | gs 兜底后可读 |
| 扫描件（无文本层）| `no-text-layer` | 不变 |
| 没装 gs | 乱码进库 | `font-encoding` 明确报错 |

> 依赖：宿主需有 `/usr/bin/gs`（fnOS 自带 Ghostscript）。没有也不影响其它格式，只是这类 PDF 会报错。
> 章节切分仍按约 5000 字一节（标题为「第 N 节」）。

实测（debug 0.0.3，`《RK3588PCB设计指导白皮书》.pdf` 36 MB）：

```
reparse 前：complete | 332 章 | 正文乱码
reparse 后：complete |  20 节 | 74 段/节，首段 "RK3588 / PCB设计指导 / 2023 / …"
```

## 17 客户端传书接口（绕过 WebDAV，2.4.0 起）

客户端直接把二进制文件 POST 给服务端，不经过 WebDAV、不需要先挂载共享文件夹。

### 17.1 独立上传令牌

服务端在 `config.json` 里维护一个**与 `apiToken` 分开**的 `uploadToken`（首次访问自动生成 32 位 hex）。
泄露上传令牌不影响 `/api/m/*` 的书架/正文读写权限，反之亦然。

- 查看/复制：设置 → 手机接入 → **传书令牌**
- 重置：`POST /api/ebook/upload/reset-token`（返回新令牌）
- 查询：`GET /api/ebook/upload` → `{enabled, token, dir, maxMB, formats[], endpoint}`

### 17.2 上传

```http
POST /api/m/ebook/upload?name=<文件名>
X-Upload-Token: <uploadToken>
Content-Type: application/octet-stream

<二进制内容>
```

也可以把令牌放 query：`...&token=<uploadToken>`。

约束：

| 项 | 值 |
| --- | --- |
| 支持格式 | `pdf` `mobi` `prc` `azw` `azw3` `epub` `txt`（`.prc/.azw` 按 mobi 处理）|
| 请求体 | **裸二进制**（`--data-binary`），**不支持 multipart/form-data**；`curl -F` 会 400 `code:"multipart"` |
| 大小上限 | `uploadMaxMB`，默认 1024 MB |
| 保存位置 | `ebookDir`（`GET /api/ebook/upload` 里的 `dir`）|
| 重名 | 自动加 ` (2)` 后缀，不覆盖已有文件 |
| 入库 | 上传后立即扫描并派发（mtime 回拨 120 秒，绕过扫描的 20 秒保护）|
| 关闭开关 | `uploadEnabled=false` 时返回 403 |

成功响应：

```json
{"ok":true,"name":"xxx.pdf","format":"pdf","size":10485760,
 "sha1":"e1a5760b…","status":"complete","path":"/vol4/1000/2/ebook/xxx.pdf"}
```

错误码：

| 场景 | 状态码 | error |
| --- | --- | --- |
| 未带/错误上传令牌 | 401 | `上传令牌无效…`，`code:"upload-token"` |
| 用了 multipart | 400 | `不支持 multipart/form-data，请用裸 body 上传`，`code:"multipart"` |
| 格式不支持 | 400 | `只支持 pdf / mobi / prc / azw / azw3 / epub / txt`，`code:"format"` |
| 超过大小上限 | 413 | `上传失败：文件超过上限（上限 N MB）` |
| 服务端关闭传书 | 403 | `服务端已关闭客户端传书` |

> 该接口**不走 `X-Api-Token`**：`/api/m/ebook/upload` 在统一鉴权里被单独放行，只校验上传令牌。

### 17.3 上传后怎么读

与扫描入库一致：`ebook://<sha1>` 进书架，`/api/toc`、`/api/content` 直接可用；
PDF 还可以切「原图」模式（见 §18）。

实测（debug 0.0.4）：

```
GET  /api/ebook/upload        → token=b67152af…，dir=/vol4/1000/2/ebook
POST ?name=upload-test.txt（错误令牌）→ 401
POST ?name=upload-test.txt（正确令牌）→ 200
     {"sha1":"8f2594bf…","status":"complete","size":110}
GET  /api/toc?url=ebook://8f2594bf…   → 2 章（第一章 上传测试 / 第二章 完）
GET  /api/content?…&index=0           → paragraphs:["这是通过客户端传书接口上传的 txt。"]
```

## 18 PDF 原页模式（图表可见）

内置 PDF 抽取只取文本，**图表不会出现在正文里**。为此增加了「原页」模式：
用 Ghostscript 把每页渲染成 PNG，阅读器按页显示完整版面（含图片/表格）。

### 18.1 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/ebook/pages` | 触发渲染 `{sha1, dpi?}`（默认 100，范围 72–200）；202 受理 |
| GET | `/api/ebook/pages?sha1=` | `{ready, count, rendering, format}` |
| GET | `/api/ebook/page/<sha1>/<n>` | 第 n 页 PNG（1 起）|
| GET | `/api/content?url=ebook://<sha1>&index=N&mode=page` | 返回 `{page:N, paragraphs:[{k:"img",t:"/api/ebook/page/…"}] , via:"ebook-page"}`；未渲染返回 409 `{needPages:true}` |

存储：`<dataDir>/ebook/books/<sha1>/pages/0001.png…`

### 18.2 阅读器

PDF 书在阅读页顶栏多一个按钮 `文 / 图`：

- `图`：按页显示原版 PNG（图表、公式、排版都在）
- `文`：回到文本层（可复制、可搜索、字号可调）
- 首次切到 `图` 会自动触发渲染并显示进度，渲染中再取页会 409 `needPages`

实测（`《RK3588PCB设计指导白皮书》.pdf`，36 MB / 194 页）：

```
POST /api/ebook/pages {sha1, dpi:100} → 202
90 秒后 GET /api/ebook/pages → {"ready":true,"count":194}
GET /api/content?…&index=0&mode=page → page:1, img=/api/ebook/page/…/1
GET /api/ebook/page/…/1 → 200 image/png 487 KB
渲染产物：194 个 PNG，共 55 MB
```

## 19 删除本地电子书（2.4.2 起）

测试或误传的条目需要能删干净（登记表、解析产物、原文件副本、书架引用）。

### 19.1 管理接口

```http
DELETE /api/ebook/delete?sha1=<sha1>[&file=1]
POST   /api/ebook/delete            {"sha1":"…","file":true}
POST   /api/ebook/delete?missing=1  # 批量删除 status=missing 的失效条目
```

- 默认删除：`index.json` 条目、`books/<sha1>/`（含 ch/pages）、`files/<sha1>.<ext>` 副本
- `file=1`：连 `ebookDir` 里的**原文件**一起删
- 书架联动：删掉 `ebook://<sha1>` 条目；把挂了该副本的网文书**改回网文源**（清 `localEbook`，`contentSource="source"`）
- 返回：`{ok, sha1, name, removedShelf, reverted, deletedSource}`

### 19.2 客户端接口（带 X-Api-Token）

```http
POST /api/m/ebook/delete
X-Api-Token: <apiToken>
{"sha1":"…","file":false}
```

响应与实现同上。

### 19.3 批量清理

`POST /api/ebook/delete?missing=1` 会一次删掉所有「原目录里已不存在」的条目
（扫描时被标为 `missing` 的测试残留、误传），返回 `{ok, cleaned, items:[sha1…]}`。

## 20 ebook-chapter：缺章时向客户端要这一章（2.4.2 起）

之前 `/api/content` 对 toc-only / partial 的书返回 `200 + needChapter`，但**没有任何人补章**：
App 只从 `/api/m/remote/pending` 领任务，不看 `/api/content`。

现在补上闭环：

1. `/api/content` 取章失败且书处于 `toc-only` / `partial` 时，服务端**先建一个 `ebook-chapter` 任务**：

   ```json
   {"type":"ebook-chapter",
    "payload":{"schema":"fnreader.ebook.v1","sha1":"…","index":5,"name":"书名",
               "format":"epub","fileUrl":"/api/m/ebook/file/<sha1>","token":"<apiToken>"}}
   ```

2. 在线设备从 `remote/pending` 领到后，用原文件取出该章，回
   `POST /api/m/remote/result {id, ok:true, data:{title, paragraphs:[{k,t}]}}`；
3. 服务端收到后**立即落盘** `ch/<index>.json`，并把这一章直接返回给网页（`via:"ebook-json"`，带 `deviceFetched:true`）；
4. 设备不在线 / 超时（20 秒）/ 回空 → 仍返回原来的 `needChapter`，网页保持「按需补章」提示。

`ebook-chapter` 已加入 `/api/remote/job` 与软总线白名单（与 `ebook-parse` 同级）。

优点：网页点开缺章时自动补齐，App 不需要额外入口；补过的章下次直接命中本地 JSON。


## 目录规范化（3.1.0+，Java 引擎移除后）

`python/legado_bridge.py` 新增 `normalize_toc` 动作，替代原 Java 引擎：

```json
// 请求
{"chapters":[{"title":"第2章 B","url":"u2"},{"title":"第1章 A","url":"u1"}]}
// 返回
{"chapters":[{"title":"第1章 A","url":"u1"},{"title":"第2章 B","url":"u2"}]}
```

规则：URL/标题去重 → 「第X章」占比 ≥70% 时剔除作者感言等杂项 → 可解析章节号占比 ≥60% 时按号稳定排序。
服务端最多等 3 秒，超时或 Python 不可用时回落 `chapter-order.js`，目录功能不受影响。

Python 进程池默认按 `max(2, min(16, CPU 核数-1))` 开 worker，可用 `LEGADO_PYTHON_WORKERS` 覆盖。

## Python 3.9 兼容与软总线解析（3.1.1+）

- `legado_bridge.py` 启动时按 `sys.version_info` 选择依赖目录：3.9 → `python/vendor39`（cp39 lxml 6.1.3），其余 → `python/vendor`（cp311）；也可用 `LEGADO_VENDOR` 显式指定
- 桥接代码已用 3.9 语法校验，`--worker` 常驻模式、`normalize_toc`、`export_txt` 在 3.9 下均可用
- 手机软总线回传的目录用 `normalizeBusChapters()` 解析：单遍扫描、兼容双编码 JSON、字段名容错、URL 去重、2 万章上限
- 目录规范化分流：≤1500 章走 Python，>1500 章走 JS（跨进程序列化不划算）
