# 本地电子书解析引擎接入规范（Text Parsing Engine）

> 适用版本：FnReader 2.2.0+
> 引擎来源：[TZYLXS/Text-Parsing-Engine](https://github.com/TZYLXS/Text-Parsing-Engine)（`server/ebook/*`）
> 本文是**接口与实现规范**，改代码或对接客户端时以本文为准。

---

## 1 定位与边界

引擎只做两件事：把本地电子书变成 `fnreader.ebook.v1` JSON，把 JSON 渲染成目录/正文。

| 格式 | 服务端 | 手机端 |
| --- | --- | --- |
| EPUB / MOBI / PRC / AZW | 兜底解析 | **优先**由在线客户端解析回传 |
| PDF | 文本层解析 | 不派发 |
| TXT | 解析 | 不派发 |

约束：

- 书 URL 固定为 `ebook://<sha1>`（40 位小写 sha1，不随解析来源变化）
- 原文件只下发一次给客户端，客户端回传 JSON 分片；服务端落盘后不再解析原文件
- 渲染只读 `book.json` 与 `ch/*.json`
- 服务端不新增 npm 依赖（只用到已有的 `cheerio`）

---

## 2 数据流

```
扫描目录（ebookDir）
  └─ 命中 epub/mobi/pdf/txt
       ├─ 计算 sha1 → 复制原文件到 <dataDir>/ebook/files/<sha1>.<ext>
       ├─ 登记 index.json（status=discovered）
       └─ bus.dispatch
            ├─ PDF/TXT ───────────────────────────────→ 本地解析（server）
            ├─ EPUB/MOBI + 有在线设备 → remote.create('ebook-parse')
            │     ├─ GET  /api/m/ebook/file/<sha1>     整本下载（支持 Range）
            │     ├─ POST /api/m/ebook/part?sha1&seq&total
            │     └─ POST /api/m/remote/result
            └─ 无设备 / 迟迟不开工 / 掉线 ─────────────→ 本地兜底（server）
```

状态机（`index.json` 每条的 `status`）：

```
discovered → queued → partial → complete
     └──────────────→ parsing（本地兜底）
     └──────────────→ failed（drm / corrupt / unsupported / kf8-unsupported / EACCES…）
```

## 3 配置项

写在 `<dataDir>/config.json`（`DEFAULT_CONFIG` 已内置默认值，可不填）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `ebookEnabled` | `true` | 总开关；false 时不扫描不派发 |
| `ebookDir` | 空 | 扫描目录；空则用 `<downloadDir>/ebook` |
| `ebookScanSec` | `60` | 定时扫描间隔（秒） |
| `ebookScanDepth` | `3` | 目录递归深度 |
| `ebookMaxMB` | `512` | 单本大小上限 |
| `ebookFallbackEnabled` | `true` | 客户端迟迟不回时是否本地兜底 |
| `ebookFallbackAfterMin` | `10` | 派发后多少分钟无进展就兜底 |
| `ebookOfflineGraceSec` | `120` | 客户端掉线宽限（秒） |
| `ebookLocalConcurrency` | `2` | 本地解析并发 |
| `ebookJobTtlMs` | `600000` | `ebook-parse` 任务存活时间 |

> `ebookDir` **不要**指向 `<dataDir>/ebook`（解析产物目录），否则会把自己的副本当新书扫到。

## 4 服务端接口

### 4.1 管理接口（网页/运维，无令牌）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/ebook/list` | `{dir, count, books:[{sha1,name,format,size,status,source,chapters,parts,error,sourcePath,file}]}` |
| POST | `/api/ebook/scan` | 立即扫一次，返回 `{root,found,added,skipped,errors}` |
| POST | `/api/ebook/reparse` | body `{sha1}`：清 `ch/`、`parts/`，状态回 `discovered` 再派发 |

### 4.2 客户端接口（需 `X-Api-Token`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/m/ebook/file/<sha1>` | 整本下载。支持 `Range: bytes=start-`，越界 416，成功 206/200；`Content-Type` 按格式 |
| POST | `/api/m/ebook/part?sha1=&seq=&total=` | 上传分片。明文 JSON ≤8 MB；支持 `Content-Encoding: gzip`（解压后 ≤20 MB）；成功 `{ok,chapters,total,received,complete}` |
| GET | `/api/m/ebook/parts?sha1=` | 断点查询 `{sha1,total,received,complete,status,parts:[seq]}` |

错误码：

| 场景 | 状态码 | 说明 |
| --- | --- | --- |
| token 缺失/错误 | 401 | 与 `/api/m/*` 一致 |
| sha1 非法 | 400 | 非 40 位十六进制 |
| 文件不存在 | 404 | 登记表无此 sha1 或原文件被删 |
| 分片超限 | 413 | 8 MB / 20 MB 限制 |
| `schema` 不匹配 | 400 | 分片被整体拒绝 |
| `sha1` 不一致 | 409 | 分片属于别的书 |
| gzip 解压失败 | 400 | — |

### 4.3 渲染接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/toc?url=ebook://<sha1>` | 返回 `{chapters:[{index,title,url,level}], name, meta, total, status, source, via:"ebook-json"}` |
| GET | `/api/content?url=ebook://<sha1>&index=N` | 返回 `{title,index,total,next,prev,paragraphs[],via:"ebook-json"}`；越界 404 |

渲染分支在 `/api/toc`、`/api/content` 最前面拦截 `ebook://`，**不会**落到书源解析逻辑。

### 4.4 软总线任务

| 项 | 值 |
| --- | --- |
| type | `ebook-parse` |
| 白名单 | `/api/remote/job` 已加入；等待上限 **240 s**（其他类型 60 s） |
| payload | 见 §5.1 |
| 结果 | `{chapters, parts, chars}`；`ok:false` 时 `error` 为错误码 |

### 4.5 启动行为

`server.listen` 之后：

```js
ebookScan.start(ctx, (config.ebookScanSec || 60) * 1000);
ebookBus.startWatchdog(ctx);
```

日志会打印 `本地电子书引擎已启动，目录: <ebookDir>` 与 `[ebook] 扫描完成 … 发现=N 新增=N`。

## 5 协议契约 `fnreader.ebook.v1`

### 5.1 任务 payload（服务端 → 手机）

```json
{
  "sha1": "4d90f9658cb18d3e6edebe7c854dccec2bcaef34",
  "name": "书名",
  "format": "epub",
  "size": 1048576,
  "fileUrl": "/api/m/ebook/file/4d90f9…",
  "token": "<本次令牌>",
  "schema": "fnreader.ebook.v1",
  "partMaxBytes": 4194304
}
```

### 5.2 part 0（清单）

```json
{
  "schema": "fnreader.ebook.v1",
  "sha1": "4d90f9…",
  "format": "epub",
  "name": "书名",
  "meta": {"title":"书名","author":"","language":"zh","publisher":"","publishedAt":"","isbn":"","description":""},
  "toc": [{"id":"ch0001","title":"第一章","level":1,"index":0}],
  "stats": {"chapters":1,"chars":2400,"parts":1}
}
```

### 5.3 part N（正文）

```json
{
  "schema": "fnreader.ebook.v1",
  "sha1": "4d90f9…",
  "seq": 1,
  "total": 2,
  "chapters": [
    {"index":0,"id":"ch0001","title":"第一章",
     "paragraphs":[{"k":"p","t":"正文"},{"k":"quote","t":"引文"},{"k":"hr","t":""}]}
  ]
}
```

约定：

- `schema` 必须完全相等；`sha1` 必须与任务一致
- `index` 全书连续、从 0 开始，与 `toc.index` 对齐
- `k` 仅允许 `p` / `h1`~`h6` / `quote` / `hr` / `img`
- `t` 是去标签纯文本，空段丢弃；`hr` 可为空
- 每片建议 ≤4 MB，按章节边界切，不拆章
- `total = 1 + 正文片数`（part 0 也算一片）

## 6 存储布局

```
<dataDir>/ebook/
  index.json                 登记表（数组）
  files/<sha1>.<ext>         原文件副本（下发用，复制后 chmod 644）
  books/<sha1>/book.json     schema/meta/toc/stats/source/status
  books/<sha1>/ch/0000.json  章节正文
  books/<sha1>/parts/0000.done  已收分片标记
```

---

## 7 实现要点与坑位

1. **20 秒保护**：文件 `mtime` 距现在 <20 s 时跳过，避免把正在拷贝的书当完整文件。
2. **排除自建目录**：扫描时跳过 `<dataDir>/ebook/files`、`<dataDir>/ebook/books`。
3. **复制后放开读权限**：部分卷/ACL 复制出来是 `0000`，解析会 `EACCES`；`scan.js` 复制后统一 `chmod 644`（本次接入修复）。
4. **长任务单独 TTL**：`remote.create(type, payload, {waitMs, ttlMs})`，`ebook-parse` 用 600 s；
   看门狗与兜底通过 `remote.abandon(id)` 撤销。
5. **不要重解析**：渲染只读 JSON；`books/<sha1>/ch/*` 缺失说明解析未完成（返回 404）。
6. **权限**：扫描目录必须对 `legado` 用户可读；NAS 上的共享文件夹要先 `chown legado` 或授权。

## 8 验收

```bash
# 1) 模块可加载
node -e "require('./legado-web/app/server/src/ebook/bus')"

# 2) 扫描目录（放一本 txt/epub，mtime >20s）
curl -X POST http://<host>:1122/api/ebook/scan
curl http://<host>:1122/api/ebook/list

# 3) 本地兜底解析（无设备时）
curl -X POST -H 'Content-Type: application/json' \
     -d '{"sha1":"<sha1>"}' http://<host>:1122/api/ebook/reparse

# 4) 渲染
curl "http://<host>:1122/api/toc?url=ebook://<sha1>"
curl "http://<host>:1122/api/content?url=ebook://<sha1>&index=0"
```

## 10 本地电子书优先：跳过客户端网文同步

**规则**：客户端同步缓存时（`POST /api/m/cache`），服务端先用书名去本地电子书登记表里匹配；
命中则**整本跳过**，不写 `cache/`、不落 `.nb`，直接返回：

```json
{"ok":true,"skipped":true,"reason":"local-ebook","message":"本地已有同名电子书，跳过客户端同步",
 "local":{"sha1":"4d90f9…","name":"黎明之剑","format":"txt","status":"complete"}}
```

匹配规则（`localEbookByName`）：

1. 书名归一化：去掉《》「」【】括号与所有空白，转小写；
2. 先找完全相等；
3. 没有再找「包含」关系，且较短一侧长度 ≥2（避免「剑」这种单字误命中）。

客户端处理建议：收到 `skipped:true` 就把这本书标记为「由 NAS 本地提供」，不再重复上传。

**关闭方式**：请求体带 `skipIfLocal:false` 可以强制走原同步流程。

## 11 客户端只有 TXT：同步 TXT 而不是 `.nb`

客户端如果手里只有 TXT（没有缓存正文），不要再传 `.nb`，改为：

```json
POST /api/m/cache
{
  "format": "txt",
  "text": "第一章 …\n　　正文…",
  "book": {"bookUrl":"…","name":"黎明之剑","author":"…"},
  "skipIfLocal": false
}
```

服务端行为：

1. 不创建 `raw/*.nb`；
2. `format === "txt"` 且 `text` 存在时，调用**本地 Python 引擎** `legado_bridge.py txt` 分章：
   - 按 `第X章 / 第X回 / 第X卷 / Chapter N` 切分（行长度 ≤40 才算标题，避免正文误判）；
   - 返回 `{name, chapters:[{index,title,paragraphs[]}], chars}`；
3. 分章结果按普通缓存章节写入 `<下载目录>/cache/<书名>/0001 标题.txt`；
4. 响应带 `"via":"local-txt"`（`.nb` 路径为 `"via":"legado"`）。

> Python 引擎不可用时返回 502 `本地 TXT 解析失败：…`，不会静默降级成乱码正文。

## 12 网页端入口：设置 → 下载 → 扫描目录

新增按钮「立即扫描」（`#scan-ebook`），行为：

1. `POST /api/ebook/scan` → `{found, added, skipped, errors}`；

## 13 解析模式开关（2.2.2 起）

设置 → 下载 → **电子书解析**，三档（默认 `proxy`）：

| 模式 | 配置值 | EPUB/MOBI 行为 | PDF/TXT |
| --- | --- | --- | --- |
| 代理解析（默认） | `proxy` | 有在线手机就派 `ebook-parse`，超时/离线本地兜底 | 本机解析 |
| 仅本机解析 | `local` | 不派手机，直接本机解析 | 本机解析 |
| 关闭 | `off` | 不扫描、不派发（已入库的书仍可读） | 不扫描 |

接口：

```http
GET  /api/ebook/settings
     → {mode:"proxy", enabled:true, dir:"/vol4/1000/Ebook/ebook", scanSec:60,
        local:0, device:1, total:1}

POST /api/ebook/settings {"mode":"local"}   // proxy | local | off
     → {ok:true, mode:"local", enabled:true}
```

实现要点：

- `ebookMode` 存在 `config.json`；`off` 时同时把 `ebookEnabled` 置 false 并跳过启动扫描；
- `bus.dispatch` 开头判定模式：`off` 直接 return，`local` 无条件 `enqueueLocal(reason='local-mode')`；
- 模式改动**立即生效**，不需要重启（扫描仍按 `ebookScanSec` 周期跑）。

## 14 扫描发现同名书 → 书架自动切到本地电子书（2.2.3 起）

**规则**：每次扫描（定时或手动）结束后，服务端把书架上的书与本地电子书按书名匹配，
命中就把**书架那条**改成 `ebook://<sha1>`，从此走本地文件，不再用网文缓存。

匹配与改写（`linkLocalEbooksToShelf`）：

1. 只看 `status` 为 `complete` / `partial` 的本地电子书；
2. 书名归一化（去书名号/括号/空白、转小写）后**完全相等**才算命中；
3. 命中后改写书架字段：

   | 字段 | 改成 |
   | --- | --- |
   | `bookUrl` / `tocUrl` | `ebook://<sha1>` |
   | `origin` / `originName` | `local-ebook` / `本地电子书` |
   | `cachedDir` | 清空（不再用缓存） |
   | `chapters` / `totalChapterNum` | 取自 `ebook` 的 toc |
   | `durChapterIndex` | 保留原进度（按新目录长度夹取） |
   | `lastChapter` / `tocVia` | 最后一章标题 / `ebook` |

4. 书架里已有同一本 `ebook://` 时，删掉旧的网文条目而不是改名（避免重复）；
5. 改名后广播 `{type:'shelf', action:'local-ebook'}`，网页书架自动刷新。

触发点：

- `ebookScan.scanOnce` 结束时回调 `ctx.afterScan`（定时扫描因此也会联动）；
- 服务启动后 4 秒补跑一次（升级前已入库的电子书立即生效）。

实测（2026-11-15，正式版）：

```
放入 /vol4/1000/Ebook/ebook/超时空犯罪集团.txt
POST /api/ebook/scan
书架：超时空犯罪集团 | ebook://62d8c3c7… | 本地电子书 | 696 章
```

> 注意：这是**破坏性改写**（原书源 URL 不再保留）。想回退时，把本地文件移出扫描目录再重新搜索添加即可。
